QuestLines Knowledge

Admin & Setup

How to add the QuestLines Knowledge bot to your own Discord server and configure it for your community — which channels it works in, auto-translation, and how the AI commands are powered. Plus operator notes for self-hosting the bot.

Adding the Bot

Add QuestLines Knowledge to your server → — you’ll need the Manage Server permission on the target server. During the invite, Discord asks you to approve a few permissions:

  • Read Messages / View Channels and Send Messages — so it can receive commands and reply.
  • Use Slash Commands — for the / commands (this is the primary way members interact with it).
  • Embed Links and Attach Files — answers are sent as rich embeds, and /newquest returns a .json file.
ℹ
Slash commands may take a moment to appear

Right after inviting, Discord can take up to an hour to surface global slash commands. If /ask doesn’t show up immediately, give it a little time.

Home vs. Guest Servers

The bot recognises one home server (the official QuestLines community) and treats every other server as a guest. Guests get the full documentation experience with a few sensible limits so the bot stays cheap and safe to run publicly.

Feature Home server Your (guest) server
Reference, search, /review Yes Yes — works everywhere, no setup
AI commands (/ask, /debug, /newquest) Shared key Require each user’s own free key via /setkey
Auto-translation On (owner-configured) Off until you enable it in /config
Community extras (e.g. /qlname banners) Yes Not available
Where ! prefix commands work A set channel All channels until you restrict them

AI Commands on Your Server

On guest servers, the AI commands run on each user’s own free Groq key — so they cost the bot owner nothing and have no cooldown. A member who hasn’t set a key is simply prompted to run /setkey.

  1. The member gets a free key at console.groq.com/keys.
  2. They run /setkey and paste it into the private popup.
  3. /ask, /debug, and /newquest now work for them.

The free reference commands (/action, /req, /search, /review, and the rest) need no key and work for everyone immediately.

Configuring with /config

/config is the admin control panel for your server. It is only visible to members with the Manage Server permission, and every reply is private.

Subcommand What it does
/config show Show this server’s current configuration (command channels, translation).
/config channels add <channel> Restrict ! prefix commands to this channel (adds to the allowlist).
/config channels remove <channel> Remove a channel from the allowlist.
/config channels clear Clear the allowlist — ! commands work in all channels again.
/config translate enable · disable Turn auto-translation on or off for this server.
/config translate channeladd <channel> Watch a channel for foreign-language messages to translate.
/config translate channelremove <channel> Stop watching a channel.
/config translate lang <code> Set the target language (messages not in this language get translated). ISO 639-1, e.g. en, es, de.

Restricting Where the Bot Responds

By default the bot responds in every channel. To keep things tidy you can confine the ! prefix commands to one or more channels: 

// Only allow !commands in #bot-commands
/config channels add #bot-commands

// Add a second allowed channel
/config channels add #questlines-help

// Go back to allowing every channel
/config channels clear
💡
Restricting slash commands

The channel allowlist above applies to ! prefix commands. Slash commands (/ask etc.) are best limited with Discord’s built-in tool: Server Settings → Integrations → QuestLines Knowledge, where you can allow or block specific channels with no bot configuration at all.

Auto-Translation

The bot can watch chosen channels and post a translation whenever someone writes in another language — handy for international communities. It is off by default on your server; opt in and pick the channels: 

// Turn it on, then choose where to watch
/config translate enable
/config translate channeladd #general
/config translate channeladd #support

// Translate anything that isn't English (the default)
/config translate lang en
ℹ
Translation relies on the bot owner’s service

Translation is powered by the bot host. If the owner hasn’t enabled the translation service, the opt-in above will have no effect — check with whoever runs the bot.

Operator Setup (Self-Hosting)

This section is for whoever runs the bot. The bot is a Node.js (discord.js) application configured through a .env file; see .env.example for the full list. The settings that matter for going public:

Setting Purpose
HOME_GUILD_ID Your server’s ID. Marks it as “home” (full features). Every other server is a guest. Home-only commands like /qlname are registered only here.
HOME_COMMAND_CHANNEL Default channel for ! commands on the home server (admins can still override per-guild with /config). Leave blank to allow all channels on home.
GROQ_API_KEY The shared key used on the home server. Guests never use it — they bring their own via /setkey.
TRANSLATE_ENABLED Master switch for the translation service. It must be true for guest /config translate opt-ins to do anything.

Going public

  1. Set HOME_GUILD_ID in .env to your server’s ID.
  2. Run node deploy.js to register the slash commands. Global commands go to every server; home-only commands (/qlname) register to the home guild only.
  3. Restart the bot, then enable Public Bot in the Discord Developer Portal, turn on the Message Content privileged intent, and share the invite link.
  4. On the App’s General Information page, set the Privacy Policy URL to your hosted copy of the Privacy Policy — recommended because the bot stores user-supplied API keys, and required if you later verify the app.
ℹ
Per-server settings live with the bot

Each guest server’s /config choices are stored by the bot (data/guild_config.json) and take effect immediately — no redeploy needed. The home-only command tools (!cfpost, !debugstats) and the supporter banner generator never appear on guest servers.
