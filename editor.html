Web Editor

A browser-based authoring tool for QuestLines configs. Drop in your mods/QuestLines/ folder, edit quests with live validation, and export a zip you can drop straight back onto the server. Everything happens in your browser — no upload, no account, no backend.

Open the Editor →

Workflow

  1. Import. Click Choose folder and select your mods/QuestLines/ directory, or drop in a zip of it. The editor recognises quests/, macros/, achievements/, and npcs.json; everything else is carried along untouched.
  2. Edit. Pick a quest from the left pane to open its pages. Each page exposes the full Hytale codec surface: title, dialog, requirements, load actions, responses, objectives, portrait overrides, and the journal-text override. Validator chips in the sidebar show which quests have errors before you even open them.
  3. Export. Click Export zip. You get a QuestLines-YYYY-MM-DD.zip with the same layout you imported. Unzip it into mods/ on your server, then run /ql reload.

Round-Trip Guarantee

Files you don't touch come back out byte-for-byte identical to the input. That means git diffs only ever show the quests you actually edited — no spurious whitespace, no key reordering, and no accidental rewrites of LocalizedText bare strings into { "en-US": "..." } objects until you add a second locale.

Auto-Save

Your work is autosaved to localStorage 1 second after each change. Reload the page and you pick up where you left off. To start fresh, clear your browser's site data or re-import a folder — the new import replaces the in-browser state.

localStorage is not a substitute for export. If you switch browsers, clear site data, or use a private window, your draft is gone. Export to zip when you stop for the day.

Graph View

Each quest can be edited in two complementary views, toggled by the Form / Graph tabs at the top of the inspector:

  • Form — the per-page editor you opened in Phase 1. Best for tuning text, requirements, actions, and individual responses.
  • Graph — an auto-laid-out node-and-edge canvas of the quest's pages. Best for understanding (and reshaping) the dialogue flow.

In Graph view:

  • Nodes are pages. They show the page id, NPC name, a snippet of the dialog, and the count of responses + outgoing links. The currently-selected page glows gold.
  • Edges are derived from page:targetId actions on responses. They flow left-to-right.
  • Missing pages — if a response navigates to a page id that has no PageData, you'll see a red dashed node so you can spot the dead link.
  • Click a node to switch back to the Form tab on that page.
  • Drag from a node's right-edge handle onto another node to create a navigation link. A new response is added to the source page with a page:target action and a placeholder label you can rename in the Form tab.
  • Click an edge and press Delete (or Backspace) to remove the underlying page: action from the response.
  • + Add page creates an empty page with the id you type and selects it.
  • Auto-layout re-runs dagre on the whole graph if the positions have drifted — useful after a flurry of edits.

Node positions are saved to localStorage, keyed by quest id. They are not written into the quest JSON, so a clean git diff after an Export zip will only show actual content changes.

Schema-Aware Autocomplete

Every requirement and action input opens a context-aware completion popup as you type. The editor knows the argument shape of the most common ~50 types and sources suggestions from the right catalog:

  • kill: → entity IDs (340+ baked from npc_catalog.json).
  • item: / break: / craft: → item IDs (3,014 baked from all_item_ids.txt).
  • page: → page IDs in the current quest.
  • questCompleted:, queststarted: → quest IDs in the project.
  • macro: → macro names in the project.
  • grantachievement: / achievement: → achievement IDs in the project.
  • addTag: / hasTag: → tags that already exist anywhere in the project (best-effort discovery).
  • timeOfDay:, moonPhase:, variable: → fixed enum values.

Keyboard nav: ↑/↓ moves the selection, Enter or Tab inserts, Esc dismisses. An empty input shows every available type grouped by category (Quest, Tracking, Inventory, Time, World, etc.) so you can discover types without leaving the tool.

Refreshing the baked item / entity catalogs after Hytale ships new content: 

cd Tools&Bots/questeditor
node scripts/bake-catalogs.mjs

Achievements & Macros

The left pane has three tabs: Quests, Achievements, and Macros. Each opens a list with validator chips and a per-item editor in the right pane.

Achievement editor

  • Edit Id, Title, Description, Category, Icon (item ID), Hidden flag, Points, Rewards rich text.
  • Single-stage achievements expose Criteria and Unlock Actions directly, both with autocomplete.
  • One-click Convert to staged achievement migrates the single-stage fields into the first stage and adds an empty second stage. Add / remove stages from the form.
  • Staged achievements support per-stage Title, Description, Points, Rewards, Criteria, and Unlock Actions. Empty Title falls back to parent + roman numeral (e.g. Slayer III).
  • Validator panel surfaces the same warnings as /ql validate: missing fields, stateful-requirement criteria, reserved-prefix tracker collisions, etc.

Macro editor

  • Edit Type (action or requirement), AnyMode (OR logic for requirement macros), and the Entries list.
  • Entries get autocomplete based on the macro type — an action macro suggests action types, a requirement macro suggests requirement types.

In-Game /qleditor

Any admin with questlines.admin can type /qleditor to receive a one-click link to the hosted web editor, already paired with the current server.

What happens under the hood:

  1. The plugin holds a persistent outbound WebSocket to the QuestLines editor relay at wss://editor.evilcraft.net:8443/relay/agent (set on plugin startup). No inbound port is opened on the Hytale server — works behind any NAT or firewall.
  2. /qleditor asks the relay for a fresh 8-character pair code, valid for 60 seconds and single use.
  3. The plugin DMs the admin a link of the form https://editor.evilcraft.net:8443/?code=K3F92Q4.
  4. The browser redeems the code at the relay, opens its own WebSocket to the relay, and the editor pulls the server's current state immediately. The code is scrubbed from the address bar so it doesn't sit in browser history.
  5. Sessions live for one hour after redemption; closing the tab and re-opening the editor in that window restores the connection without a new /qleditor call.

One-time setup

relay_enabled=true ships as the default. On first run, the plugin generates a per-server identity (relay_server_id + relay_server_key) and persists it in QuestLines.conf — nothing for admins to paste. 

# ── 13. Editor Relay ──
relay_enabled=true
relay_url=wss://editor.evilcraft.net:8443/relay/agent
relay_server_id=<auto-generated UUID>
relay_server_key=<auto-generated 32-byte secret>

Keep relay_server_id and relay_server_key stable across restarts so editor sessions stay associated with this server. Wiping both lines forces a fresh identity on the next save.

Self-hosting the relay

The relay is a small Node.js process (single file, no database, fine on a Raspberry Pi 3b). The source lives in Tools&Bots/relay/ in the QuestLines repo, alongside a Caddyfile and systemd unit. Self-hosters point relay_url at their own relay and the editor at https://<their-host>/editor. See Tools&Bots/relay/README.md in the repo for the install steps.

Troubleshooting

  • "Editor relay is not connected" — the plugin hasn't reached the relay yet. Reconnects run with exponential backoff; check the server log for [Relay] entries to see the most recent error. Common causes: outbound HTTPS blocked by firewall, DNS failure on the relay host, or a typo in relay_url.
  • "Server is offline" in the editor — the relay reachable, but this server's plugin isn't connected to it. Check the same [Relay] log on the server side.
  • Pair code rejected — codes expire after 60 seconds and are single-use. Run /qleditor again.
  • "Unsafe attempt to load URL" — the in-game Hytale webview blocks some URL patterns. Copy the URL from the second line of the /qleditor output into a real browser.

Sync Behaviour

What gets transferred

The server's quests/, macros/, achievements/ directories and npcs.json. Files are sent as raw text over the relay, so the editor's byte-identical round-trip guarantee carries through — unchanged files come back exactly as they were.

Anything else in the plugin folder (players.json, portraits, the conf file itself, wavearenas) is never read or written by the relay.

Conflict policy

The relay is last-write wins. If two admins edit simultaneously (one in-game via /ql quest, one in the browser), the second push overwrites the first writer's changes. Pull right before you push if anyone else might be editing.
