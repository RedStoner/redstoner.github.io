UI Theming

Every QuestLines screen — the dialogue box, the journal, quest boards, the goal HUD, the in-game editor — is drawn from Hytale UI markup that ships inside the plugin. This page explains where the colors live and the three ways to re-skin them: tuning config keys, editing the shipped .ui files, and (for a handful of values) rebuilding from source.

How QuestLines UI Is Styled

QuestLines uses Hytale's native UI system. Each screen is built from a layout file written in Hytale UI markup, shipped inside the plugin's asset pack at Common/UI/Custom/questlines/*.ui. At runtime a screen's Java class loads its layout (for example cmd.append("questlines/Dialogue.ui")) and then injects dynamic content into it.

Colors and styling come from three distinct places. Knowing which layer a given color lives in tells you how to change it:

  1. Stock Hytale styles. Every layout starts with $C = "../Common.ui";, which resolves to Hytale's own Common.ui — not a QuestLines file. Window frames ($C.@DecoratedContainer), titles ($C.@Title), scrollbars, separators and default buttons all inherit Hytale's base theme from here. Re-theming these means overriding stock Hytale UI, which is outside QuestLines' scope.
  2. Hardcoded values in QuestLines' own .ui files. Anything QuestLines styles itself — the dialogue response buttons, HUD backgrounds, panel insets — is hex-coded directly in the layout files. These are fully editable without recompiling.
  3. Java-computed inline colors. A few dynamic elements (dialogue response button tints, journal category tabs, goal-HUD label colors) have their colors built as strings in Java and injected at runtime. These are baked into the compiled plugin and can only be changed by editing the source and rebuilding — see Values That Require a Source Build below.
ℹ
There is no theme config file

QuestLines does not ship a "theme.json" or a swappable color palette. Re-skinning is done by tuning the handful of color keys in QuestLines.conf and by editing the layout files in the asset pack. Plan your theme around those two surfaces.

No-Recompile Config Keys

Before touching any layout file, check whether a config key already exposes what you want. These live in QuestLines/QuestLines.conf and take effect on /ql reload — no jar editing, no restart.

KeyDefaultControls
response_default_color (empty) Base hex tint for dialogue response buttons (e.g. #2b3542). Hover, pressed and disabled states are auto-derived by brightening/darkening this color. A per-response Color set in the quest overrides it; when both are empty the built-in #2b3542 is used.
response_default_opacity 100 Background opacity (0–100) applied to response buttons. Lower values let the game world show through. Overridable per response with BackgroundOpacity.
default_hud_position TopRight Default anchor corner of the Quest Goal HUD for new players (TopRight, TopLeft, BottomRight, BottomLeft). Players can change their own via /qlconfig.
default_hud_offset_x / default_hud_offset_y 10 / 10 Default pixel offset of the goal HUD from its anchor corner, for new players.
dialog_width_full / dialog_width_mid / dialog_width_compact 20 / 350 / 570 Horizontal anchor inset (pixels from the left edge) for each dialogue width preset. Larger values make the box narrower and push it right.

Example QuestLines.conf snippet for a warm, semi-transparent button theme:

response_default_color=#5a3a2b
response_default_opacity=80
default_hud_position=BottomRight
default_hud_offset_y=150

How Hytale Loads UI Files

QuestLines declares "IncludesAssetPack": true in its manifest, so the whole Common/ tree inside the jar — including every .ui file — is registered with the server as an asset pack. When a screen loads questlines/Dialogue.ui, Hytale resolves it from that pack.

Hytale tracks each pack with a source that determines precedence when two packs share the same identifier. From highest to lowest priority:

SourceWhere it comes fromPriority
CLIPack passed explicitly on the server command lineHighest
CLASSPATHBuilt-in / bundled packs↑
MODSJars in the server's mods/ folder (this is QuestLines)↓
RUNTIMEPacks registered live (e.g. the in-game asset editor)Lowest

A higher-priority pack with the same identifier as QuestLines (net.evilcraft:QuestLines) replaces the lower one entirely. Two different packs that both ship the same identifier are rejected as a duplicate. In practice this means the dependable way to re-theme is to change the files inside the QuestLines pack itself, covered next.

Re-Skinning the Layout Files

This is the main theming workflow. You edit the layout files that ship in the QuestLines jar, then put the modified jar back in mods/.

  1. Make a backup copy of questlines-<version>.jar.
  2. A jar is a zip. Open it with any archive tool (or jar xf questlines-<version>.jar Common/UI/Custom/questlines/) and find the layout files under Common/UI/Custom/questlines/.
  3. Edit the hex colors / styles in the .ui file(s) you want to re-theme.
  4. Write the changed files back into the jar (jar uf questlines-<version>.jar Common/UI/Custom/questlines/Dialogue.ui), drop it back into mods/, and restart the server.
⚠
Re-apply on every update

Edits made inside the jar are lost when you install a new QuestLines build. Keep your theme changes as a small patch/diff so you can re-apply them after each upgrade, and re-check the layout files in case they changed.

Worked example: re-skinning dialogue response buttons

The response button style is defined near the top of Common/UI/Custom/questlines/Dialogue.ui. The shipped version is a cool slate blue: 

@ResponseButtonStyle = TextButtonStyle(
    Default:  ( Background: #2b3542, LabelStyle: (TextColor: #cccccc, Wrap: true) ),
    Hovered:  ( Background: #3a4a5c, LabelStyle: (TextColor: #ffffff, Wrap: true) ),
    Pressed:  ( Background: #1e2a38, LabelStyle: (TextColor: #aaaaaa, Wrap: true) ),
    Disabled: ( Background: #1a2030, LabelStyle: (TextColor: #555555, Wrap: true) ),
    Sounds: $Sounds.@ButtonsLight
);

To make it a warm parchment theme, change the four Background values (and text colors to taste):

@ResponseButtonStyle = TextButtonStyle(
    Default:  ( Background: #6b4a2f, LabelStyle: (TextColor: #f3e6c8, Wrap: true) ),
    Hovered:  ( Background: #845c3a, LabelStyle: (TextColor: #ffffff, Wrap: true) ),
    Pressed:  ( Background: #523722, LabelStyle: (TextColor: #d8c4a0, Wrap: true) ),
    Disabled: ( Background: #3a2a1c, LabelStyle: (TextColor: #6b5a45, Wrap: true) ),
    Sounds: $Sounds.@ButtonsLight
);
ℹ
Static style vs. quest-driven color

This @ResponseButtonStyle block styles fixed buttons such as Continue and Cancel. The actual per-response answer buttons are tinted dynamically in Java from response_default_color (or the quest's own per-response Color). For a coherent look, set response_default_color to match your edited style.

Worked example: the goal HUD background

QuestGoalHUD.ui draws the on-screen quest tracker. Its panel background and outline are plain hex with alpha: 

Group {
    LayoutMode: Top;
    Background: #000000(0.4);     // 40% opaque black
    Padding: (Full: 8);
    OutlineColor: #000000(0.6);
    OutlineSize: 1;
    ...
}

Change #000000(0.4) to any hex/alpha pair — e.g. #1a0f28(0.55) for a translucent purple panel. There are four HUD layout variants (QuestGoalHUD.ui, _Bottom, _BottomLeft, _BottomRight, _TopLeft) for the different anchor positions — edit each one you want to match.

Color & Style Syntax

The Hytale markup used in the .ui files supports:

  • Hex color — Background: #2b3542
  • Hex with alpha — #000000(0.4) (the parenthesised number is opacity, 0.0–1.0)
  • Style reference — Style: $C.@DefaultScrollbarStyle (pulls from stock Hytale Common.ui)
  • Inline label styling — Style: (TextColor: #ffffff, FontSize: 14, RenderBold: true, Wrap: true)
⚠
Markup gotchas that crash the client

A malformed layout file disconnects players at load. Keep these rules in mind when editing:

  • Text wrap is Wrap: true — not WrapText.
  • HorizontalAlignment accepts only Center or Start (never Left/Right).
  • Element IDs are camelCase and cannot contain underscores.
  • Use plain ASCII only in any visible text — no arrows, bullets, em-dashes or accents.
  • $C.@Name references resolve against stock Common.ui; don't invent new @-styles expecting them to exist there.
  • Groups can't take a bare hex color in every context the way buttons/labels can — when in doubt, copy the pattern from a working sibling element.

Values That Require a Source Build

A handful of colors are generated in Java and injected at runtime, so they are not in the .ui files and can't be changed by editing the asset pack. Re-theming these requires editing the source and rebuilding the plugin.

ElementSource fileShipped colors
Per-response answer button tint ui/DialogueUI.java Derived from response_default_color (config) — prefer the config key
Journal category tabs (selected/idle) ui/QuestJournalUI.java #253040 / #1a2030, accent #4a90d9, text #667788
Goal HUD label colors ui/QuestGoalHud.java Title #e8d48b, body #cccccc, sub #999999
ℹ
Building from source

QuestLines builds with Gradle 9. After editing the inline color strings, rebuild and deploy the jar like any other change — there is no automated test suite, so verify the affected screens in-game. The response button tint should almost always be themed via the response_default_color config key instead of source edits.

Testing Your Theme

  • Config-only changes apply on /ql reload — no restart.
  • Edited .ui files require a server restart, since the asset pack is read from the jar at startup.
  • If a screen fails to open or players disconnect on open, the layout file has a parse error — check the server console for the failing file and re-read the markup gotchas above. A broken first element cascades into bogus "selector not found" errors for later elements, so fix the earliest reported problem first.
  • Test every width preset and HUD anchor variant you touched — they are separate files.
