UI Theming

Re-skin the QuestLines NPC dialogue — colours, sizes, background images, transparency, the whole window frame — by shipping a small override asset pack. Nothing is edited inside the QuestLines jar and nothing is rebuilt from source: you drop a pack in mods/ and Hytale's last-loaded-wins asset resolution does the rest.

ℹ
One method: an override pack

Editing the files inside questlines-<version>.jar is no longer a supported workflow — those edits are lost on every update and are easy to get wrong. The supported way to theme QuestLines is to ship a separate asset pack that replaces the layout files at their original paths. The dialogue window is purpose-built for this: its entire look comes from one variables file you can override on its own.

How QuestLines UI Is Styled

QuestLines uses Hytale's native UI system. Each screen is built from a layout file written in Hytale UI markup, shipped inside the plugin's asset pack at Common/UI/Custom/questlines/*.ui. At runtime a screen's Java class loads its layout (for example cmd.append("questlines/Dialogue.ui")) and injects the dynamic content into it.

The NPC dialogue window goes one step further: every piece of it — the static shell and everything generated at runtime (response buttons, the item turn-in picker, dialogue body text, inline icons) — is defined in .ui files, and all of its colours, sizes and backgrounds live in a single variables file, DialogueTheme.ui. Override that one file and you retheme the whole dialogue. No plugin code is involved.

A handful of dynamic colours are still computed in Java and are not part of the asset-pack theme surface (see Values Computed at Runtime). For the dialogue, the only such case — the per-response answer-button tint — is controlled by a config key, not by editing code.

How Hytale Loads UI Files

QuestLines declares "IncludesAssetPack": true in its manifest, so the whole Common/ tree inside the jar — including every .ui file — is registered with the server as an asset pack. When a screen loads questlines/Dialogue.ui, Hytale resolves it from that pack.

When several packs ship a file at the same client path, Hytale resolves the collision with one rule: last loaded wins. Each path maps to a list of contributing packs, and the client is sent only the last entry. So a later-loaded pack can shadow a file that an earlier pack — including stock Hytale or QuestLines — already ships, without touching the original jar.

"Last" is decided by load order, computed from manifest dependencies. Stock Hytale is a core pack and loads first; QuestLines loads after it; and a pack that declares a dependency on QuestLines loads after QuestLines. That dependency is how an override pack guarantees it wins the collision against a QuestLines file.

Building an Override Pack

An override pack is a tiny asset-only pack — no Main class, no code. It needs:

  1. A manifest.json with a unique identifier (a Group + Name that differ from every installed pack), "IncludesAssetPack": true, and a dependency on net.evilcraft:QuestLines so it loads after Core and wins the path collision.
  2. The replacement file(s) at the identical path they have in QuestLines, e.g. Common/UI/Custom/questlines/DialogueTheme.ui. The pack only needs to contain the files you are replacing — you do not mirror the whole asset tree.
  3. Drop the folder (or a zip of it) into the server's mods/ folder and restart.
MyTheme/
  manifest.json
  Common/
    UI/
      Custom/
        questlines/
          DialogueTheme.ui      <-- your override (recolour / resize the dialogue)
          golden/               <-- (optional) your own textures, referenced from the theme
            window.png

A minimal manifest.json for an asset-only override pack:

{
  "Group": "com.example",
  "Name": "MyDialogueTheme",
  "Version": "1.0.0",
  "ServerVersion": ">=0.5.0-pre.9 <0.6.0",
  "Description": "Custom QuestLines dialogue theme.",
  "IncludesAssetPack": true,
  "Dependencies": {
    "net.evilcraft:QuestLines": "*"
  }
}
ℹ
Survives QuestLines updates

Because your theme is a separate pack, installing a new QuestLines build never wipes it. The one thing to re-check after a big upgrade is whether the layout's structure changed — if a new build reworks Dialogue.ui, a full Dialogue.ui override can go stale. Overriding only DialogueTheme.ui (just the variables) is the most upgrade-proof choice.

Theming the Dialogue Window

The dialogue's look is fully driven by these .ui files under Common/UI/Custom/questlines/. Override only the ones you need:

FileRole
DialogueTheme.uiThe variables file. Every colour, size, and named button/label style. Override this to retheme everything.
Dialogue.uiThe static window shell (containers, panels, separator, portrait slots). Imports the theme.
DialogueResponse.uiOne response row (button + optional item-icon cell + optional typed-input field).
DialoguePickerItem.uiOne row in the "choose an item to turn in" picker.
DialogueTextSegment.uiOne line/segment of dialogue body text (a Label).
DialogueIconRow.uiA horizontal host for a dialogue line that mixes text with inline {icon:...} icons.
DialogueIconSegment.uiOne inline {icon:itemId} item icon.

For a recolour or resize you only need DialogueTheme.ui. Its tokens are grouped at the top of the file (colours, dimensions) with named styles below them. The most-used colour tokens:

TokenControls
@ColDialogTextBody text of the NPC's dialogue.
@ColNpcNameThe "Name:" label above the dialogue.
@ColResponseBg / ...BgHover / ...BgPress / ...BgDisableResponse button background per state.
@ColResponseText (+ Hover/Press/Disable)Response label colour per state.
@ColResponseOutlineResponse button outline colour.
@ColPickerText (+ Hover/Press)Item turn-in picker label colour.
@ColInputBg / @ColInputPlaceholderText/number input field background + placeholder text.

And the dimension tokens (all plain pixel values):

  • @ResponseSpacing, @ResponsePadH, @ResponsePadV, @ResponseOutlineSize — response button spacing, padding and outline thickness.
  • @IconCell / @IconInner — the item-icon cell beside a response and the icon inside it.
  • @InlineIconSize — {icon:...} icons rendered inside dialogue text.
  • @InputHeight / @InputPadH — a response's typed-input field.
  • @PickerRowHeight, @PickerIconSize, @PickerBtnPadH, @PickerFontSize — the item turn-in picker rows.

Below the tokens are the named styles — @ResponseButtonStyle, @ContinueButtonStyle, @PickerCancelStyle, @PickerButtonStyle, @NpcNameStyle, @DialogTextStyle, @PickerPromptStyle, @InputPlaceholderStyle — built from the tokens. Edit a token to recolour everywhere it is used, or edit a named style for finer control of one element.

⚠
A full DialogueTheme.ui replacement must define every token

Dialogue.ui and the templates reference these tokens by name. If your override replaces the whole file, it must keep every @-token that the shipped file defines (including @DialogHeight / @DialogBottom) — a missing name fails to resolve and the dialogue won't open. The safe approach is to copy the stock DialogueTheme.ui and edit values in place.

Backgrounds, Images & Transparency

The window frame is hand-built in Dialogue.ui (not the stock @DecoratedContainer), so every surface is a theme token and can take a colour, a custom image, or be made transparent:

TokenSurface
@WindowBackgroundThe dialogue body panel — the main "UI background".
@TitleBackgroundThe title bar strip.
@DividerBackgroundThe divider between the text and the responses.
@DecorationTop / @DecorationBottomThe top / bottom frame flourishes.
@DialogBoxBackground / @ResponsePanelBackgroundThe left (text) / right (responses) panels — transparent by default.
@CloseButtonStyleThe close (X) button textures.

Supplying an image

Assign a PatchStyle with a texture path:

@WindowBackground  = PatchStyle(TexturePath: "MyPack/dialog_bg.png", Border: 24);
@DividerBackground = PatchStyle(TexturePath: "MyPack/divider.png");

Border 9-slices the image so its corners/edges stay crisp at any window size; omit it for a plain stretch. You can also fade an image with the Color field: PatchStyle(TexturePath: "MyPack/dialog_bg.png", Color: "#ffffff(0.6)").

⚠
Texture paths are relative to the .ui file

A texture path resolves relative to the directory of the .ui file the path literal sits in — here Common/UI/Custom/questlines/. Ship your own art alongside the theme (e.g. a golden/ subfolder) and reference it as "golden/window.png". To reach a stock Hytale texture under Custom/Common/ (one level up), prefix it with ../, e.g. "../Common/ContainerPatch.png" — which is exactly what the shipped defaults do. A bare "Common/..." would resolve to the non-existent questlines/Common/... and the image silently fails to load.

Transparency

Every colour token accepts an alpha suffix, so any surface can be faded or made fully clear:

  • #2b3542(0.8) — 80% opaque.
  • #2b3542(0.0) or the built-in @Transparent — fully clear (paints nothing).
  • #rrggbbaa — the 8-digit hex form also works.

Use it on any @Col* token or any *Background token. For a fully see-through "glass" window, set @WindowBackground / @TitleBackground to translucent colours (e.g. #101522(0.5)) and @DecorationTop / @DecorationBottom to @Transparent.

Window Size

The dialogue window's height and its gap from the bottom of the screen are theme tokens: 

@DialogHeight = 300;   // window height (px)
@DialogBottom = 20;    // gap from the bottom edge of the screen (px)

These resolve at parse time on the outer container, which QuestLines never mutates at runtime — so overriding DialogueTheme.ui resizes the dialog with no plugin code change. (A full theme replacement must define both tokens, since they are referenced by name.)

The window width is chosen per-page (the Full / Mid / Compact option on each page) and applied at runtime to the inner content wrapper. The actual inset values live in QuestLines.conf (dialog_width_full / dialog_width_mid / dialog_width_compact), not in the theme file — see No-Recompile Config Keys.

Restructuring the Dialogue

Recolouring is just the theme file. To change layout — move the response icon, rework the frame, restyle the body text rows — override the relevant template or the shell. The one rule: keep the element ids QuestLines addresses, or the runtime content wiring won't find its targets.

  • Response button (DialogueResponse.ui): keep #ResponseButton, #ResponseRow, #IconLeft/#IconLeftImg, #IconRight/#IconRightImg, #ResponseInputText, #ResponseInputNumber.
  • Dialogue text: restyle via @DialogTextStyle, or override DialogueTextSegment.ui.
  • Whole window frame (Dialogue.ui): keep #ResponsesContainer, #Dialog, #NPCName, #RightPanel, #PickerContainer, #PickerItems, #ContinueButton, #CloseButton, #DialogSeparator, and the portrait containers.

QuestLines fills these templates by appending them and descending into named children — e.g. cmd.append("#ResponsesContainer", "questlines/DialogueResponse.ui") then setting #ResponsesContainer[i] #ResponseButton.TextSpans. The developer docs and docs/UI.md describe this append + #Container[i] pattern in full.

Example: the Golden Glass Pack

QuestLines ships a complete worked example: Golden Glass, a theme where the window, title and panels are translucent dark glass and every edge, frame and button carries a golden accent. It lives in the repo at server/ThemeOverrideTest/ and is exactly the override-pack shape described above:

Download the Golden Glass pack (.zip)

  • Common/UI/Custom/questlines/DialogueTheme.ui — the single override. It points every frame/button/divider/decoration background at the golden/ PNGs, sets warm-gold text colours, and bumps @DialogHeight / @DialogBottom to show a theme controlling the window size.
  • Common/UI/Custom/questlines/golden/*.png — the gold-on-glass art (9-sliced translucent panels and buttons, divider, flourishes, close-button states).
  • _gen_golden_textures.py — a reproducible Python + Pillow generator for every PNG; tweak the palette at the top and re-run to restyle the art.
  • manifest.json — an asset-only pack (no Main class) that declares a hard dependency on net.evilcraft:QuestLines purely to load after Core so its DialogueTheme.ui wins.

Copy that folder, rename it (give it a unique manifest identifier), and edit DialogueTheme.ui to build your own theme.

No-Recompile Config Keys

Some look-and-feel values are exposed as config keys rather than theme tokens. These live in QuestLines/QuestLines.conf and take effect on /ql reload — no pack, no restart.

KeyDefaultControls
response_default_color (empty) Base hex tint for the dynamic per-response answer buttons (e.g. #2b3542). Hover, pressed and disabled states are auto-derived. A per-response Color set in the quest overrides it; when both are empty the built-in #2b3542 is used.
response_default_opacity 100 Background opacity (0–100) applied to those response buttons. Lower values let the game world show through. Overridable per response with BackgroundOpacity.
default_hud_position TopRight Default anchor corner of the Quest Goal HUD for new players (TopRight, TopLeft, BottomRight, BottomLeft). Players can change their own via /qlconfig.
default_hud_offset_x / default_hud_offset_y 10 / 10 Default pixel offset of the goal HUD from its anchor corner, for new players.
dialog_width_full / dialog_width_mid / dialog_width_compact 20 / 350 / 570 Horizontal anchor inset (pixels from the left edge) for each dialogue width preset. Larger values make the box narrower and push it right.

Example QuestLines.conf snippet for a warm, semi-transparent button theme:

response_default_color=#5a3a2b
response_default_opacity=80
default_hud_position=BottomRight
default_hud_offset_y=150
ℹ
Theme + config should agree

The per-response answer buttons are tinted from response_default_color in Java, not from DialogueTheme.ui. For a coherent look, set response_default_color to match the response colours in your theme (the theme's @ResponseButtonStyle drives the fixed Continue / Cancel and picker buttons).

Overriding Other UI Files

The same override-pack mechanism works for any QuestLines layout file — the journal, quest boards, the goal HUD, the in-game editor — and for stock Hytale files. Only the dialogue has the clean DialogueTheme.ui token layer; for the others you place an edited copy of the whole .ui file at its original path in your pack. See the Layout File Reference for which file drives which screen.

Overriding stock Common.ui (server-wide reskin)

Window frames, titles, scrollbars and default buttons that QuestLines (and every other plugin) pull in via $C = "../Common.ui"; are defined in Hytale's Common/UI/Custom/Common.ui. Because that file also resolves last-loaded-wins, an override pack can replace it at the same path.

⚠
This is a global, server-wide change

Overriding Common.ui restyles every UI that imports it — QuestLines, all other plugins, and vanilla Hytale screens alike. It is the right tool for a cohesive server-wide theme and the wrong tool if you only want to restyle QuestLines (use the dialogue theme for that). Keep every @-style name other files reference — removing one breaks every layout that imports it — and test broadly before shipping.

Color & Style Syntax

The Hytale markup used in the .ui files supports:

  • Hex color — Background: #2b3542
  • Hex with alpha — #000000(0.4) (the parenthesised number is opacity, 0.0–1.0) or the 8-digit #rrggbbaa form
  • Image patch — PatchStyle(TexturePath: "MyPack/x.png", Border: 16) (Border 9-slices; add Color: "#ffffff(0.6)" to tint/fade)
  • Style reference — Style: $C.@DefaultScrollbarStyle (pulls from stock Hytale Common.ui), or $Theme.@ResponseButtonStyle (pulls from DialogueTheme.ui)
  • Inline label styling — Style: (TextColor: #ffffff, FontSize: 14, RenderBold: true, Wrap: true)
⚠
Markup gotchas that crash the client

A malformed layout file disconnects players at load. Keep these rules in mind when editing:

  • Text wrap is Wrap: true — not WrapText.
  • HorizontalAlignment accepts only Center or Start (never Left/Right).
  • Element IDs are camelCase and cannot contain underscores.
  • Use plain ASCII only in any visible text — no arrows, bullets, em-dashes or accents.
  • Texture paths resolve relative to the .ui file; use ../Common/... to reach stock textures from questlines/, never a bare Common/....
  • $C.@Name references resolve against stock Common.ui; $Theme.@Name against DialogueTheme.ui. Don't reference a name that isn't defined in the file you're importing from.
  • A full DialogueTheme.ui override must define every token the shipped file defines — a missing token fails to resolve and the dialogue won't open.

Values Computed at Runtime

A few dynamic colours are generated in Java and injected at runtime, so they are not in the .ui files and an asset pack can't change them. They are listed here so you know what an override pack does not reach — not as an invitation to edit code.

ElementHow it's set

Testing Your Theme

  • Config-only changes (QuestLines.conf) apply on /ql reload — no restart.
  • An override pack is read from disk at startup, so adding or changing one needs a server restart.
  • Open a dialogue by talking to a quest-giver NPC. If it opens in the stock blue/grey look instead of your theme, check the server console for the asset-pack load line naming your pack and for any duplicate-asset or .ui parse warnings — a pack that didn't load (missing dependency / clashing identifier) won't win the collision.
  • If a screen fails to open or players disconnect on open, the layout file has a parse error. Check the console for the failing file and re-read the markup gotchas above; a broken first element cascades into bogus "selector not found" errors for later elements, so fix the earliest reported problem first.
  • Test every width preset and, if you touched the goal HUD, every anchor variant you changed — they are separate files.
