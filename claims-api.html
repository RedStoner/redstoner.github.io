Claims Plugin

Developer API

The public extension surface for other plugins — the transaction ledger listener, claim-event hooks, access interceptors, and external ownership resolvers.

Claims exposes a public extension surface for other plugins through QuestLinesClaimsAPI. Obtain it from the loaded plugin instance once setup has completed: 

QuestLinesClaimsPlugin claims = (QuestLinesClaimsPlugin) server.getPlugin("QuestLinesClaims");
QuestLinesClaimsAPI api = claims.getApi();

All API methods must be called from the server main thread. The data objects returned by the facade (AdminRegion, PlayerClaim, RegionMember) expose setters for internal use only — mutate through the dedicated API methods so saves and map invalidation happen correctly.

ClaimsTransactionListener

Subscriber surface for rent / renew / buy / refund economy events. Carries the full Claims-side context VaultUnlocked itself cannot supply (region id, region type, world, the receiving guild for guild halls) plus a Claims-generated transactionId for ledger correlation, and for refunds the parentTransactionId of the original charge being reversed.

The intended consumer is an external economy / audit / ledger plugin that wants to journal Claims transactions. Listeners run on the server main thread — keep them cheap and offload heavy work to async tasks, using ctx.transactionId as the foreign key for the async write.

Lifecycle

Each charge attempt that passes Claims-side preflight (player can afford, region is in a chargeable state, requester is the tenant where relevant) fires a sequence of callbacks on the same listener. All three callbacks receive the same ClaimsTransactionContext instance — the transactionId and timestampMillis are stable across the sequence.

  1. onClaimsTransactionPending(ctx) — fires immediately before economy.withdraw is invoked. No money has moved and no Claims state has been mutated. ctx.balanceAfter is null. Ledger plugins record the attempt here.
  2. One of:
    • onClaimsTransaction(ctx) — fires after Vault reports EconomyResponse.SUCCESS and Claims has committed the region change (tenant set, lease extended, owner transferred). ctx.balanceAfter carries the post-debit balance Vault reported. Ledger marks the row committed.
    • onClaimsTransactionFailed(ctx, reason) — fires when Vault rejects the withdraw or throws. No Claims state was mutated and the player was not charged. ctx.balanceAfter is null. Ledger marks the row failed.

Pre-withdraw rejections (region not available, not the tenant, insufficient funds, Vault plugin missing at the top of the call) produce no callbacks — Claims surfaces them only through the RentResult / RenewResult / BuyResult return value of the action that triggered the charge.

Refunds

When the config flag refund_on_reset=true is set, Claims credits a pro-rated refund to the tenant whenever a lease ends early. The refund fires the same pending / committed / failed lifecycle as a charge, but with ctx.type == REFUND; ctx.amount is the refunded value (always non-negative — direction is implied by the type) and the deposit goes to the tenant rather than from them.

Refund math: price × max(0, leaseEnd - now) / (durationSeconds × 1000), clamped to the full price. Past-expiry leases (post-grace reset) yield zero and the refund event is skipped entirely — no zero-amount event fires.

ctx.refundReason identifies why the lease ended early (LEASE_EXPIRED, ADMIN_RESET, TENANT_ABANDON). ctx.parentTransactionId points back at the original RENT or RENEW charge being reversed, so a ledger can link the credit row to the original debit row. The parent-id mapping lives in memory only — refunds fired after a server restart will have parentTransactionId == null; the ledger can fall back to correlating by region + payer in that case.

For guild halls, the refund also debits the receiving guild via the ExternalOwnershipResolver.onRegionIncome hook with a negative amount, so guild books stay balanced.

Correlating with Vault

VaultUnlocked emits no events and has no transaction-id concept, so there is no Vault-side handle to correlate against. The Claims-generated ctx.transactionId is the canonical ledger key. The ctx.balanceAfter field on the committed callback is captured directly from Vault’s EconomyResponse.balance, so a ledger can detect drift by periodically comparing against Economy.getBalance without making a follow-up Vault call on every transaction.

Example

// Soft-import pattern — no compile-time dependency on Claims
try {
    Class.forName("net.evilcraft.questlinesclaims.api.QuestLinesClaimsAPI",
                  false, getClass().getClassLoader());
    QuestLinesClaimsPlugin claims = (QuestLinesClaimsPlugin)
            server.getPlugin("QuestLinesClaims");
    claims.getApi().registerTransactionListener(new ClaimsTransactionListener() {
        @Override
        public void onClaimsTransactionPending(ClaimsTransactionContext ctx) {
            ledger.insertPending(ctx.transactionId, ctx.timestampMillis,
                                 ctx.payerUuid, ctx.regionId, ctx.amount);
        }

        @Override
        public void onClaimsTransaction(ClaimsTransactionContext ctx) {
            // type      = RENT | RENEW | BUY
            // payee*    = null for server plots; GUILD + guildId for guild halls
            // balanceAfter = post-debit balance Vault reported
            ledger.markCommitted(ctx.transactionId, ctx.balanceAfter);
        }

        @Override
        public void onClaimsTransactionFailed(ClaimsTransactionContext ctx,
                                              FailureReason reason) {
            ledger.markFailed(ctx.transactionId, reason.name());
        }
    });
} catch (ClassNotFoundException e) {
    // Claims not installed — skip
}

ClaimsTransactionContext fields

FieldTypeMeaning
transactionIdUUIDFresh per charge attempt. Stable across pending / committed / failed. Use as ledger primary key.
timestampMillislongSystem.currentTimeMillis() captured when the attempt began. Frozen across the lifecycle.
typeTransactionTypeRENT | RENEW | BUY | REFUND
payerUuidUUIDPlayer being charged (or credited, for refunds).
regionId / regionNameStringPersistent id and display name of the region.
regionTypeStringPlot kind (see table below).
worldNameStringWorld the region is in.
regionOwnerType / regionOwnerUuidClaimOwnerType, UUIDnull for server-owned plots (gold sunk to server); GUILD + guild id for guild halls (gold credited to guild on charge, debited on refund).
amountBigDecimalAmount moved. Always non-negative — direction is implied by type (debit for RENT/RENEW/BUY, credit for REFUND).
balanceAfterBigDecimalPost-transaction balance Vault reported. Populated only on the committed callback; null on pending and failed.
parentTransactionIdUUIDREFUND only. The transactionId of the original RENT or RENEW being reversed, if Claims still has it in memory. null for non-refunds and for refunds after a server restart.
refundReasonRefundReasonREFUND only. LEASE_EXPIRED | ADMIN_RESET | TENANT_ABANDON. null for non-refunds.

The regionType string identifies the kind of plot the charge was for — useful for categorising income by plot kind. Stable values:

regionType Plot
rentStandard server-owned rent plot.
buyStandard server-owned buy plot.
guild_rentGuild hall rent — regionOwnerType is GUILD, regionOwnerUuid is the guild id.
guild_buyGuild hall buy — same payee semantics as guild_rent.

FailureReason values

FailureReasonCause
VAULT_REJECTEDVault returned EconomyResponse.FAILURE. Typically a race between the canAfford check and the withdraw call.
VAULT_NOT_IMPLEMENTEDVault returned EconomyResponse.NOT_IMPLEMENTED for this currency.
VAULT_THREWVault threw an exception inside withdraw.
ECONOMY_UNAVAILABLEVault became unavailable between preflight and withdraw (rare).

All Vault-side failures fold into the existing ECONOMY_UNAVAILABLE value of the public RentResult / RenewResult / BuyResult return enums — UI consumers continue to show the same “Economy is unavailable” message and do not need a new switch arm. The precise reason is delivered only through the listener.

ClaimEventListener

Subscriber surface for claim chunk-removal events. Fires after a chunk has been removed from any PlayerClaim — whether by /unclaim, admin unclaim, external-owner unclaim, or cascade from a deleted claim row. Intended for plugins that maintain side-tables keyed by chunk (e.g. share-grant rows in a federation plugin) so they can drop their rows when the chunk goes away. 

claims.getApi().registerClaimEventListener(new ClaimEventListener() {
    @Override
    public void onClaimChunkRemoved(ClaimOwnerType ownerType,
                                    UUID ownerUuid,
                                    String worldName,
                                    int chunkX, int chunkZ) {
        // drop side-table rows keyed by (worldName, chunkX, chunkZ)
    }
});

PlayerClaimAccessInterceptor

Hook called during access resolution on PLAYER-typed claims for actors who are neither the owner nor a listed member, before the claim’s memberDefaultFlags are consulted. Multiple interceptors may be registered — they are consulted in registration order and the first non-null result wins. Returning null defers to the next interceptor (and ultimately to the default flags).

Used by federation plugins to grant the surrounding city or nation access to a player’s claim without modifying the claim’s member list. Returning a populated Set<RegionFlags> overrides the default access for that actor. 

claims.getApi().registerPlayerClaimAccessInterceptor((claim, actorUuid) -> {
    if (sharedWithCity(claim, actorUuid)) return EnumSet.of(RegionFlags.INTERACT);
    return null; // defer
});

ExternalOwnershipResolver

Adapter for non-PLAYER claim owner types — guilds, nations, cities, parties, or any other grouping defined by another plugin. Registered per ClaimOwnerType: 

claims.getApi().registerOwnershipResolver(ClaimOwnerType.GUILD, new ExternalOwnershipResolver() { /* … */ });

The resolver is consulted whenever Claims needs to decide whether an actor is an owner-like principal of the claim, look up the actor’s effective member flags, gate claim creation on the owner’s behalf, enforce the owner’s chunk limit, or report income on guild-hall rent/buy transactions. Multiple plugins can coexist by registering resolvers for distinct owner types (e.g. one for GUILD, another for NATION + CITY).
