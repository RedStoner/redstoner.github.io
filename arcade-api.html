Arcade Plugin

Developer API

ArcadeAPI is the public facade for other plugins. Use it to enumerate games, snapshot live matches, route a player into a game, and listen for match start/end events. Stable signatures — breaking changes track the engine’s major version.

ℹ
Optional manifest dependency

Add Arcade to your plugin’s manifest as an optional dependency to compile against net.evilcraft.questlinesarcade.api. Guard every API access with a presence check — ArcadeAPI.get() returns null before Arcade has finished setup and after it shuts down.

Getting the API

import net.evilcraft.questlinesarcade.api.ArcadeAPI;

ArcadeAPI api = ArcadeAPI.get();
if (api == null) {
    // Arcade not installed / not started / shut down
    return;
}

The singleton is installed during Arcade’s setup() and cleared during its shutdown(). Cache the reference only for the duration of a single operation; for long-lived hooks, re-resolve through get() each time.

Discovery

Enumerate the games every installed pack has registered, optionally filtered by category.

MethodReturnsUse
listGames() List<GameInfo> Every registered game, registration order.
findGame(gameId) Optional<GameInfo> Lookup by id.
gamesByCategory(category) List<GameInfo> Games tagged with that Category.

GameInfo exposes id, displayName, description, howToPlay, categories, capabilities (min/max players, turn-based, spectators allowed, supports rejoin), gameMode, and casinoBetAmount.

Match Introspection

Snapshot any live match. All MatchInfo values are immutable point-in-time captures — safe to share across threads.

MethodReturnsUse
activeMatches() List<MatchInfo> Every live match.
activeMatchesOfGame(gameId) List<MatchInfo> Live matches for one game.
findMatch(matchId) Optional<MatchInfo>By UUID.
findMatchByCode(code) Optional<MatchInfo>By short code.
matchOfPlayer(uuid) Optional<MatchInfo>Match the player is currently in.
isInMatch(uuid) boolean Cheap check.
activeMatchCount() int Live match count.
matchCapacity() int Engine-wide cap from maxConcurrentMatches.
queueSize(gameId) int How many are waiting in that game’s queue.
queueSnapshot(gameId) List<UUID> Queue contents oldest-first.

Routing Players

All routing calls return a JoinResult whose status is one of SUCCESS, QUEUED, GAME_NOT_FOUND, MATCH_NOT_FOUND, MATCH_FULL, MATCH_NOT_JOINABLE, ALREADY_IN_MATCH, INSUFFICIENT_FUNDS, PLAYER_OFFLINE, AT_CAPACITY, or INTERNAL_ERROR. On success the result carries the matchId and matchCode.

MethodBehaviour
queuePlayer(uuid, gameId)Drop the player into a queue. If the queue then fills, the engine creates the match and seats every player automatically.
joinMatch(uuid, matchId)Seat the player into an existing LOBBY match.
joinMatchByCode(uuid, code)Same, but lookup is by the short code.
openMatch(uuid, gameId)Create a fresh match for the game and seat the caller. Force-starts immediately if the game’s maxPlayers is 1 — great for solo quest rewards.
removePlayer(uuid)Yank the player out of whatever queue + match they’re in. Forfeits if the match is RUNNING.
openLobby(uuid)Pop open the standard /arcade lobby for that player.

Match Events

Subscribe with addMatchStartListener / addMatchEndListener and unsubscribe with their remove twins. Both fire from the engine thread that drives the match; keep callbacks fast or post their work to your own executor. 

api.addMatchEndListener(event -> {
    if (!event.outcome().equals(MatchEndEvent.Outcome.WIN)) return;
    for (UUID winner : event.winners()) {
        myQuestPlugin.awardXp(winner, 100);
    }
});

MatchEndEvent exposes matchId, matchCode, gameId, gameDisplayName, terminalState, outcome, winners, participants, note, startedAt, and endedAt (plus a duration() helper).

Recipes

Send a player into a quest-driven solo game

ArcadeAPI api = ArcadeAPI.get();
if (api == null) return;
JoinResult r = api.openMatch(playerUuid, "minesweeper");
if (r.status() != JoinResult.Status.SUCCESS) {
    chat(playerUuid, "Couldn't start Minesweeper: " + r.message());
}

Award XP only for wins

api.addMatchEndListener(event -> {
    if (event.outcome() != MatchEndEvent.Outcome.WIN) return;
    if (event.winners().isEmpty()) return;
    for (UUID winner : event.winners()) {
        myXpService.grant(winner, 50);
    }
});

Quick-queue from a chat command

// "/quickchess" -> instant queue for Chess
JoinResult r = api.queuePlayer(playerUuid, "chess");
switch (r.status()) {
    case SUCCESS, QUEUED -> chat(playerUuid, "Queued for Chess.");
    case INSUFFICIENT_FUNDS -> chat(playerUuid, "You need 1 token.");
    case ALREADY_IN_MATCH -> chat(playerUuid, "Finish your current match first.");
    case PLAYER_OFFLINE, AT_CAPACITY, INTERNAL_ERROR -> chat(playerUuid, "Try again later.");
    default -> chat(playerUuid, r.message());
}

List in-progress matches

for (MatchInfo m : api.activeMatches()) {
    System.out.printf("%s [%s] %d/%d players%n",
        m.gameDisplayName(), m.state(),
        m.players().size(), m.connectedPlayers().size());
}

Threading and Stability

  • Listeners fire on engine threads. Avoid blocking them; route side-effects (database writes, network calls) to your own executor.
  • Routing calls are thread-safe. queuePlayer, openMatch, joinMatch*, and removePlayer may be called from any thread.
  • Player-facing UI opens on the world thread. Routing methods take care of the world-thread hop internally; you do not need to schedule it yourself.
  • API stability: the contract documented in net.evilcraft.questlinesarcade.api.package-info ties signature-breaking changes to a major-version bump. New JoinResult statuses or MatchEndEvent fields can appear in minor releases; handle unknown enum values defensively.
