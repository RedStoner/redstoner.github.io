Denizens Plugin

Behavior & AI

The Behavior block drives how a Denizen acts in the world — where it looks, how it moves, what animations it plays, how tough it is, and what happens when it dies.

Attitude

Behavior.Attitude sets the Denizen’s disposition toward players. It maps to the engine’s native attitude system.

ValueMeaning
PASSIVENever fights back.
NEUTRALDefault. Ignores players unless provoked.
AGGRESSIVEAttacks players in range.
HOSTILEActively hostile.

Attitude can also be overridden per player and temporarily from a quest with the setAttitudeP: action.

Look-At

Behavior.LookAt turns the Denizen’s head. Modes:

ModeFieldsEffect
OFF—No head tracking (default).
NEAREST_PLAYERRange (default 8.0)Track the closest player within range.
FIXED_YAWFixedYawHold a fixed facing in degrees.

Look-at can be changed live from a quest with the lookAt: action — no respawn needed.

Wander

Behavior.Wander makes the Denizen roam randomly around its anchor. A new point is picked after a random idle pause between MinIdleSec and MaxIdleSec.

KeyDefaultNotes
EnabledfalseTurn wandering on.
Radius6.0Max distance from the anchor.
MinIdleSec4.0Shortest pause between moves.
MaxIdleSec12.0Longest pause between moves.
ℹ
Behavior precedence

Full precedence: Schedule › Guard › Patrol › Wander › Idle. Guard preempts everything else when a hostile is in range (even a scheduled activity), so a patrolling Guard breaks off to fight then resumes patrol.

Patrols

Behavior.Patrol walks the Denizen through an ordered list of waypoints with pathfinding. Author waypoints in the editor’s Waypoints tab.

Patrol keyDefaultNotes
EnabledfalseTurn the patrol on.
Looptruetrue loops back to the first waypoint; false ping-pongs back along the path.
FrozenfalseHeld in place. Persisted — a frozen patrol stays frozen across respawn / restart. Toggle with /denizen patrol freeze|resume.
Waypoints[]The ordered waypoint list (below).

Each waypoint:

Waypoint keyDefaultNotes
X / Y / Z0Waypoint position.
WaitMinSec / WaitMaxSec0Random dwell window on arrival. Both 0 = no pause.
DwellModeIDLEIDLE stands still; WANDER micro-wanders inside WanderRadius while dwelling.
WanderRadius0Micro-wander radius for WANDER dwell mode.
ArriveAnim—One-shot animation (Action slot) on arrival.
IdleAnim—Looped animation (Status slot) while dwelling; overrides the Behavior idle animation.
LeaveAnim—One-shot animation (Action slot) just before leaving.
 
"Behavior": {
  "Patrol": {
    "Enabled": true,
    "Loop": true,
    "Waypoints": [
      { "X": 100, "Y": 65, "Z": -200, "WaitMinSec": 2, "WaitMaxSec": 5 },
      { "X": 112, "Y": 65, "Z": -200, "DwellMode": "WANDER", "WanderRadius": 3 }
    ]
  }
}

Patrols can also be frozen / resumed from a quest with the freezePatrol: and resumePatrol: actions.

Guard

Behavior.Guard turns a Denizen into an active protector: it engages hostile targets inside ProtectRadius and returns to a configurable standby point when no threat is in sight. Guard sits between Schedule and Patrol in the precedence ladder, so a patrolling Guard breaks off to fight and then resumes patrol once the area clears.

ℹ
Attitude-driven combat

Targeting is translated into per-target attitude overrides at runtime (role.getWorldSupport().overrideAttitude(targetRef, …)), and the role's native Component_Sensor_Sight_By_Attitude handles target acquisition + lock from there. The base Attitude in this tab stays in effect for non-matching entities — Guards never aggro anyone the runtime hasn't whitelisted.

Guard keyDefaultNotes
EnabledfalseMaster toggle. Without it the block is inert; with it, the runtime adds Effective.GUARD to the precedence ladder.
ProtectRadius16.0Blocks. Acquisition radius for the periodic scan (~2/sec). An engaged target stays "in range" until they leave roughly radius × 1.25 — hysteresis prevents flicker at the edge.
HostileTo[][]Patterns the Guard attacks on sight. See the token table below.
FriendlyTo[][]Patterns the Guard always considers allies. Carve exceptions out of a broad Hostile pattern (e.g. HostileTo: [Player] + FriendlyTo: [RedStoner]).
NeutralTo[][]Patterns ignored even if they hit the Guard (no retaliation). Lowest priority of the three lists.
LeashModeANCHORWhere the Guard holds station between fights — ANCHOR / PLAYER / NPC. See the leash modes below.
LeashTargetnullUsername for PLAYER, Denizen name / #shortId / UUID for NPC. Ignored for ANCHOR. Offline / wrong-world targets silently fall back to the anchor.
FollowDistance3.0Side offset from the leash subject, in blocks. Positive = right shoulder, negative = left. Ignored for ANCHOR.
LeadDistance0.0Forward offset along the leash subject's facing yaw, in blocks (signed). Positive = walks ahead, zero = beside, negative = trails behind. Ignored for ANCHOR.
PackTagnullGroup identifier for formation behavior. Formation runtime is not yet shipped — the field round-trips for forward compatibility but Guards currently act solo.
AllegiancenullReference point for relationship tokens (see below). Format city:<name> or nation:<name>. Without an allegiance, relationship tokens silently never match; literal city/nation membership tokens still work.

Leash modes

ModeStandby behavior
ANCHORReturn to the Denizen's spawn anchor. FollowDistance / LeadDistance ignored — the anchor is the post.
PLAYERStand near the named player. With LeadDistance=0, FollowDistance=3 the Guard rides the player's right shoulder; LeadDistance=3 walks them three blocks ahead; LeadDistance=-3 trails. Bodyguard / escort mode.
NPCStand near another Denizen (referenced by name, #shortId, or UUID). Same facing-based math as PLAYER. Useful for follower chains and (eventually) pack leaders.

Target token grammar

Each entry in HostileTo / FriendlyTo / NeutralTo can be any of the following. The classifier evaluates them in priority order Friendly › Hostile › Neutral — the first list to match a player wins, so an explicit Friendly entry beats a broad Hostile pattern. When LeashMode=PLAYER the LeashTarget player is implicitly Friendly even without an explicit FriendlyTo entry — a bodyguard never auto-attacks its charge.

TokenMatches
StevePlayer whose username is exactly Steve (case-insensitive).
Hostile_*Wildcard glob against the username. * = any chars, ? = one char.
PlayerSpecial token — matches every player.
[Steve,Alex,Bot_*]Bracket list. Matches if any inner pattern matches.
city:ArdoniaPlayer is a member of the named city. Needs QuestLinesNations.
nation:Ardonia_LeaguePlayer's city belongs to the named nation. Needs QuestLinesNations.
city:HOSTILEPlayer's city has an active CityWar with the Guard's Allegiance city. Needs Nations and an Allegiance.
city:ALLYPlayer's city has an active CityAlliance with the Allegiance city.
nation:HOSTILEPlayer's nation has an active NationWar with the Allegiance nation (Allegiance may be city-form — the bridge follows the city's owning nation).
nation:ALLYPlayer's nation has an active NationAlliance with the Allegiance nation.
ℹ
Optional dependency: QuestLinesNations

Without QLN installed the NationsBridge stays inert and every city: / nation: token silently returns no-match. The literal / wildcard / Player patterns still work, so a Guard configured with only those entries behaves identically on a server with or without Nations.

ℹ
NPC vs NPC targeting

NPC patterns like Bunny, Goblin*, *Boss match against an entity's NPCEntity.getNPCTypeId() (the role id). The scan runs per-Guard every ~500ms; same {@code Friendly > Hostile > Neutral} priority as players. Player-only tokens (Player, city:, nation:) silently skip when matched against NPCs. 

// Tavern bouncer — stationary, attacks anything player except Steve, ignores barkeep NPC.
"Guard": {
  "Enabled": true,
  "ProtectRadius": 12.0,
  "HostileTo": ["Player"],
  "FriendlyTo": ["Steve"],
  "LeashMode": "ANCHOR"
}

// Personal bodyguard — walks 2 blocks ahead of "Aldric", attacks his nation's enemies.
"Guard": {
  "Enabled": true,
  "ProtectRadius": 18.0,
  "HostileTo": ["nation:HOSTILE", "city:HOSTILE"],
  "FriendlyTo": ["nation:ALLY", "Aldric"],
  "LeashMode": "PLAYER",
  "LeashTarget": "Aldric",
  "FollowDistance": 2.5,
  "LeadDistance": 2.0,
  "Allegiance": "city:Ardonia"
}
ℹ
Role-template requirement

The native Guard instruction state lives in QLD_Template_Citizen.json and is inherited by every variant (incl. QLD_PlayerNPC). Custom roles that don't ship a Guard instruction state will still accept Behavior.Guard.Enabled=true, but when the runtime flips them into the Guard native state they'll find no matching sensor block and the body will stay idle. Author custom roles to mirror the shipped three-tier structure (sight-by-attitude → maintain-distance + combat ability → return-to-GuardTarget-slot).

Animations

Set an idle and a moving animation that play automatically based on the Denizen’s state. The Animation editor tab sets the animation ids; the animation slots default sensibly and are only overridable in JSON.

KeyDefault slotPlays when…
IdleAnimIdStatusThe Denizen is stationary.
MoveAnimIdMovementThe Denizen is moving / wandering.

Override the slot with IdleAnimSlot / MoveAnimSlot (valid slots: Movement, Status, Action, Face, Emote). You can also fire one-off animations from a quest with the playAnim: / clearAnim: actions.

ℹ
Valid animation ids are per-model

Animation ids come from the role’s own animation set — what’s valid depends on the model. Use ids that exist on the chosen role.

Combat & Survival

The remaining Behavior fields govern how durable a Denizen is and what happens when it dies. They live on the Behavior and Combat editor tabs.

KeyDefaultNotes
InvulnerabletrueGod-mode. Defaults on so quest NPCs can’t be farmed; set false for a killable mob.

KnockbackScalerole default0 = immovable, 1 = normal knockback.
LeashDistance32.0How far the Denizen may stray from its anchor.
RespawnOnDeathtrueAuto-respawn after being killed.
RespawnDelaySec30.0Delay before respawning.
HealOnRespawntrueRestore to full health on respawn.
