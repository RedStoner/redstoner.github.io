Permissions & Integrations

The questlinesmmo.* permission tree and its defaults, plus how the plugin integrates with QuestLines Claims and cron scheduling.

Permissions

Permissions follow a flat questlinesmmo.<feature>.<action> layout. The full set is given in the player and admin command tables on the UI & Commands page. A few umbrella nodes are worth highlighting:

PermissionDefaultDescription
questlinesmmo.adminfalseGatekeeper for the entire /qlmmo admin hierarchy.
questlinesmmo.qlmmo.reloadfalseRequired for /qlmmo reload.
questlinesmmo.qlmmo.poi.*falseAuthoring permissions for POI definitions.
questlinesmmo.guildtrueOpen the /guild shortcuts UI.
questlinesmmo.guild.createtrueRequired to create a new guild.
questlinesmmo.guild.hometrueEnter your guild hall.
questlinesmmo.dungeon.entertrueRequired to take a party into a dungeon.
questlinesmmo.discoveriestrueOpen the player Discoveries panel.

Per-feature nodes (questlinesmmo.party.*, questlinesmmo.friend.*, questlinesmmo.lfg.*, questlinesmmo.guild.perms.*, etc.) all default to allowing players to use the relevant command. Restrict them by denying explicitly in your permission manager.

Integrations

QuestLines Claims

When QuestLines Claims is installed, the bridge in net.evilcraft.questlinesmmo.bridge.ClaimsBridge is loaded and guild halls delegate chunk protection, plot management, and wilderness rules to Claims. The bridge is fully isolated — with Claims absent, no Claims classes are referenced and the plugin loads normally; per-mode wilderness toggles in config.guildHall become no-ops.

Guild plots (/guild hall plot rent|buy) reuse the standard /claim wand selection workflow. Guild plots are stored separately from admin Claims regions and intentionally do not support prefab saving — that workflow is reserved for admin regions.

Cron Scheduling

World boss spawns are evaluated by an internal cron parser. Standard five-field expressions are supported (minute, hour, day-of-month, month, day-of-week). Spawn timestamps are persisted to bosses/schedule_state.json so a missed window after a server restart is detected and recovered to (the next valid time fires immediately on startup if appropriate).
