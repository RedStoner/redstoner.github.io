Titles Plugin

QuestLines Titles

A player title system for Hytale servers. Grant players richly formatted titles as quest rewards, display them as chat prefixes, and let players choose their active title from a selection UI.

How It Works

QuestLinesTitles maintains two stores: a server-wide title catalogue (titles.json) that defines every available title, and per-player title data that records which titles each player has unlocked and which one is currently active.

Titles are awarded through QuestLines actions (giveTitle:), admin commands (/titleadmin grant), or directly via the developer API. Once a player owns at least one title they can open /title to browse their collection and set an active title. The active title is then exposed to chat plugins and PlaceholderAPI.

ℹ
Standalone or with QuestLines Core

QuestLinesTitles works as a standalone plugin. The QuestLines integration (actions, requirements, and the {title} variable) is automatically enabled when QuestLines Core is also installed on the server.

titles.json

All available titles are defined in mods/QuestLinesTitles/titles.json. The file is created with a set of defaults on first start and can be edited directly or updated via /titleadmin ui. The order of categories and titles within a category is preserved on disk and used for display order in the /title selector — reorder by drag in the admin UI or by reshuffling the JSON keys.

Each entry is keyed by a unique title ID (convention: category:name) and carries a category string and a value display string. The display string supports rich formatting — see Title Formatting below. 

{
  "misc:newcomer": {
    "category": "misc",
    "value":    "&3Newcomer"
  },
  "misc:king": {
    "category": "misc",
    "value":    "{#FFAA00}{b}King{/}{/}"
  },
  "pvp:champion": {
    "category": "pvp",
    "value":    "<gradient:#FF4444:#FFAA00>Champion</gradient>"
  },
  "builder:artisan": {
    "category": "builder",
    "value":    "<rainbow>Artisan</rainbow>"
  },
  "donor:king": {
    "category":   "misc",
    "value":      "{#FFAA00}{b}King{/}{/}",
    "permission": "questlinestitles.title.king"
  }
}
Field Required Description
category No (defaults to misc) Groups related titles together in the selection UI. Can be any string.
value No (defaults to the ID) The display text shown in chat, the UI, and placeholders. Supports rich formatting tags.
permission No Permission node that dynamically grants the title while the player holds it. See Permission-Granted Titles.
source No Predefined source category id used for “How to get” hints on locked titles. See How-to-Obtain Hints.
sourceDetail No Free-text detail shown beneath the source label in the player UI.
visible No (defaults to the global / per-category default) When false, the title is hidden from players who have not yet unlocked it. Owned titles are always shown. Omit to inherit from config.json.

Permission-Granted Titles

A title with a permission field is automatically considered owned by any player holding that permission node - no /titleadmin grant or giveTitle: action required. This is ideal for rank-based or donor-tier titles managed by a permissions plugin.

Ownership is evaluated dynamically at read time. A title appears in the player's /title UI, satisfies hasTitle: requirements, and can be set active as long as the permission is held. When the permission is revoked the title disappears on the player's next login and the active selection is cleared.

ℹ
Dynamic + persistent grants stack

/titleadmin grant and giveTitle: write a persistent unlock that is independent of the permission check. A permission-configured title granted that way stays owned even if the permission is later removed - use this as an admin override.

ℹ
Online-only evaluation

Permission checks require the player to be online. Admin views like /titleadmin list <offlinePlayer> show only persistent unlocks for offline targets. 

// titles.json
"donor:king": {
  "category":   "donor",
  "value":      "{#FFAA00}{b}King{/}{/}",
  "permission": "questlinestitles.title.king"
}

Hidden Titles & Categories

Titles can be hidden from the /title selection UI until a player owns them. Visibility is resolved in three layers — per-title override, per-category override, then a global default. Owned titles are always shown regardless of these settings.

Global defaults and per-category overrides live in mods/QuestLinesTitles/config.json, which is created with defaults on first start: 

{
  "defaultVisible":     true,
  "categoryVisibility": {
    "secret": false,
    "pvp":    true
  }
}
Field Description
defaultVisible Default “Show to players” state for titles and categories without an explicit override. Defaults to true, preserving the pre-1.2 behaviour where every title is shown.
categoryVisibility Per-category overrides keyed by category name (lowercase). Categories not listed inherit defaultVisible.

Individual titles can override their category with the visible field on the title entry in titles.json. Omit it to inherit. The admin UI exposes the same toggle as a Show to players checkbox on both the category and the title edit row.

ℹ
Owned titles always show

A player who has unlocked a title always sees it in their /title UI, even if the title or its category is marked hidden. Hiding only affects the locked-title preview surface.

Title Formatting

Title values support three overlapping formatting syntaxes. All three are parsed by the same formatter and can be mixed freely in a single value string.

Brace Tags

Tag Effect
{b}text{/}Bold
{i}text{/}Italic
{u}text{/}Underline
{m}text{/}Monospace
{#RRGGBB}text{/}Hex color (3- or 6-digit)
{link:URL}text{/}Clickable link
{/}Closes the innermost open tag

XML-style Tags

Tag Effect
<b>text</b> or <bold>Bold
<i>text</i> or <italic>Italic
<u>text</u> or <underlined>Underline
<m>text</m> or <monospace>Monospace
<#RRGGBB>text</#RRGGBB>Hex color
<gold>text</gold>Named color (Minecraft palette: gold, red, aqua, green, etc.)
<rainbow>text</rainbow>Per-character rainbow colors
<gradient:#FF0000:#0000FF>text</gradient>Color gradient (2+ stops)
<url:https://...>text</url>Clickable link

&-Codes

Standard Minecraft &X codes are supported. A color code resets all active formatting before applying the new color.

Code Effect
&0–&9, &a–&fMinecraft color palette
&lBold
&oItalic
&rReset all formatting
 
// &-code color + bold
"&6&lLegend"

// Brace-tag hex color with bold
"{#FFAA00}{b}King{/}{/}"

// XML gradient
"<gradient:#FF4444:#FFAA00>Champion</gradient>"

// Tags can nest freely
"{b}{#FF55FF}Grand{/} Explorer{/}"

Commands

Player Commands

Command Permission Description
/title none Opens the title selection UI. Players can browse their unlocked titles and set one as active.

Admin Commands

All /titleadmin subcommands require the questlinestitles.admin permission. Authoring changes inside /titleadmin ui save back to titles.json automatically; to pick up external edits to titles.json or config.json, restart the server — there is currently no standalone reload subcommand.

Command Description
/titleadmin grant <username> <titleId> Unlock a title for a player. No-op if they already own it.
/titleadmin remove <username> <titleId> Revoke a title from a player. Also clears active title if it was the removed one.
/titleadmin set <username> [titleId] Equip a title as the player’s active worn title. The player must already own the title (use grant first). Omit titleId to clear the active title.
/titleadmin list <username> List all titles a player has unlocked.
/titleadmin available List all titles defined in titles.json.
/titleadmin ui <username> Open the admin title management UI, optionally viewing a specific player’s data.

QuestLines Integration

When QuestLines Core is installed alongside QuestLinesTitles, the following actions, requirements, and text variables are automatically registered with the QuestLines engine.

ℹ
Auto-detected at startup

No extra configuration is needed. QuestLinesTitles detects QuestLines Core at runtime and registers the integration automatically. A log line confirms: [Titles] QuestLines detected – registering requirements, actions & variables.

Actions

Action Description
giveTitle:<titleId> Unlock the specified title for the player. No-op if already owned.
removeTitle:<titleId> Revoke the specified title from the player. Also clears active title if it matches.
setTitle:<titleId> Equip the specified title as the player's active worn title. Fails silently if the player does not effectively own it (use giveTitle: first, or grant the configured permission). Pass an empty id (setTitle:) to clear the active title.

How-to-Obtain Hints

Each title can carry an optional source hint shown to players who don’t yet own it. In the admin UI’s title edit row, pick a Source category from the dropdown and write any extra context into How to get.

In the player’s /title UI, locked titles are shown alongside owned ones (greyed out, not clickable to equip) unless hidden by the visibility settings described in Hidden Titles & Categories. Clicking a locked title surfaces its “How to get” line in the info panel.

Stored on the title’s JSON entry as:

{
  "id":           "pvp:champion",
  "category":     "pvp",
  "value":        "&4&lChampion",
  "source":       "quest",
  "sourceDetail": "Complete the Tournament questline"
}

Built-in source values:

  • quest — Quest
  • achievement — Achievement
  • event — Event
  • donation — Donation
  • rank — Rank / Permission
  • purchase — In-game Purchase
  • secret — Hidden / Secret
  • other — Other

Both source and sourceDetail are optional. The info panel is hidden when neither field is set, so existing titles render unchanged.

Requirements

Requirement Passes when…
hasTitle:<titleId> The player has unlocked the specified title (whether or not it is active). Passes for permission-granted titles while the permission is held.
titleActive:<titleId> The player’s currently active title is the specified title.

Text Variable

Variable Replaced with…
{title} The player’s active title as plain text (all formatting stripped). Empty string if no title is active. 
// Quest response action: award a title on quest completion
"Actions": [
  "questCompleted:dragon_slayer",
  "giveTitle:pvp:dragonslayer",
  "message:You earned the title: {title}!"
]

// Requirement: only show page if player has the title
"Requirements": [ "hasTitle:pvp:dragonslayer" ]

Nameplate Display

The active title is automatically appended to each player’s nameplate (the label rendered above their head in-world). By default the plugin writes <title> <username> into the native Hytale Nameplate component, stripping colors and formatting tags so the engine’s name renderer can display the value.

When NameplateBuilder is installed the plugin detects it at startup and instead registers a title segment with the NameplateBuilder API (segment id title, enabled by default for players, refreshed every 20 ticks plus on title-change). This lets server admins reorder, restyle, or disable the title alongside other nameplate segments without conflict. See NameplateBuilder under Integrations.

Integrations

Every integration below is optional and auto-detected at startup — install the partner plugin and QuestLinesTitles wires itself in. None of them need to be configured on the Titles side.

NameplateBuilder

When NameplateBuilder is installed, QuestLinesTitles registers a title segment (display name Player Title) targeted at players. The segment is enabled by default, refreshes every 20 ticks, and is force-pushed whenever the player’s active title changes. While NameplateBuilder is active the plugin stops writing the native Nameplate component directly so the two systems don’t fight over it.

VaultUnlocked

When VaultUnlocked is installed, QuestLinesTitles registers as a ChatUnlocked provider. Chat plugins that consume VaultUnlocked’s chat API will automatically receive the player’s active title as a chat prefix.

PlaceholderAPIs

QuestLinesTitles ships expansions for three Hytale PlaceholderAPI implementations. All three resolve to the player’s currently active title with {…} formatting tags stripped, retaining &-codes and §-codes for downstream color-code processing. An empty string is returned when the player has no active title.

Provider Placeholder Notes
HelpChat PlaceholderAPI %title% Identifier title; persistent expansion.
CreeperFace PlaceholderAPI 2.0 {title} Visitor-sensitive placeholder registered under the GlobalScope.
WiFlow PlaceholderAPI {title_active} (or any {title_*}) Expansion identifier title; works in EssentialsPlus chat formats.

Storage

Per-player title state (unlocked titles, unlock timestamps, and the active title) is persisted through a pluggable backend selected by the storage block in mods/QuestLinesTitles/config.json. The default is a flat-file backend, so existing servers need no changes. Server admins running the QuestLines suite on a shared database can point Titles at the same SQLite / MySQL / MariaDB instance. 

"storage": {
  "backend":     "file",
  "host":        "localhost",
  "port":        3306,
  "database":    "questlinestitles",
  "user":        "root",
  "password":    "",
  "useSsl":      false,
  "extraParams": ""
}
Field Description
backend file (default), sqlite, mysql, or mariadb. file stores one JSON file per player; the database backends share a single store.
host / port / database / user / password Connection settings for the mysql / mariadb backends. Ignored by file and sqlite.
useSsl Whether to negotiate SSL with the database server. MySQL / MariaDB only.
extraParams Extra JDBC URL parameters appended to the connection string (e.g. &serverTimezone=UTC). MySQL / MariaDB only.
Backend Where data lives
file mods/QuestLinesTitles/playerdata/<uuid>.json — one file per player.
sqlite mods/QuestLinesTitles/titles.db — an embedded database, no server required.
mysql / mariadb Tables title_players and title_unlocks on the configured server. Bundled drivers connect via MariaDB Connector/J (speaks to both).
ℹ
Keyed by UUID — migration is automatic

Title data is keyed by player UUID (rename-safe). Older builds keyed by username (playerdata/<username>.json); those files are adopted automatically the first time each player connects after the upgrade, and re-keyed under their UUID. Switching from file to a database backend likewise imports each player's legacy file on their next join — no manual migration step.

Granting a title with /titleadmin grant <name> to a player who has never joined still works: the grant is held as a pending record and applied when that player first connects. Targeting an offline player by name otherwise requires them to have joined at least once (so their UUID is known).

File Layout

File Purpose
mods/QuestLinesTitles/titles.json Server-wide title catalogue. Edit to add, rename, or remove titles.
mods/QuestLinesTitles/config.json Global plugin configuration: the defaultVisible toggle and categoryVisibility overrides used by Hidden Titles & Categories, plus the storage backend block.
mods/QuestLinesTitles/playerdata/<uuid>.json Per-player title state (unlocked titles, timestamps, active title) for the file backend. See Storage for the database backends.

Permissions

Permission Default Description
questlinestitles.admin false Required for all /titleadmin subcommands.
<custom node> false Any node referenced in a title's permission field dynamically grants that title while held. Node name is server-defined (e.g. questlinestitles.title.king). See Permission-Granted Titles.
