Claims Plugin

Integrations

How Claims plugs into the rest of the server — VaultUnlocked economy, the world map, ECS enforcement systems, portal protection, claim decay, and imports from other claims plugins.

VaultUnlocked

Rent and buy features require VaultUnlocked. At startup Claims probes for net.cfh.vault.VaultUnlockedServicesManager; if absent, economy is disabled, and rent/buy transactions return ECONOMY_UNAVAILABLE. Withdrawals and refunds go through the standard Vault economy object so any Vault-backed currency plugin works transparently.

World Map

Claims installs its own IWorldMapProvider that draws the usual terrain plus an overlay of claim colours and admin region boundaries. Invalidation is automatic: claiming, unclaiming, renaming, or recolouring a claim triggers a redraw of the affected chunks plus their neighbours.

ECS Systems

Several ECS systems run alongside the listener-based protection to cover engine events that aren’t delivered through the regular listener API:

  • ClaimTitleSystem — shows a short title announcement when a player crosses into a new claim or region: the claim or region name for owned land, “Wilderness” for unclaimed land.
  • EntryEnforcementSystem — remembers the player’s last allowed position and teleports them back when they enter a position where the ENTRY flag is denied. Admins bypass this check.
  • ExplosionBlockDamageSystem — intercepts global (non-player) block damage events — primarily explosions — and cancels them when the EXPLOSIONS flag is denied at the affected block.
  • SpawnPreventionSystem — removes vanilla mob spawns inside admin regions where the SPAWN flag is denied. Plugin-triggered spawns (identified by an unset spawn-configuration index) pass through untouched, so HyCitizens NPCs and scripted spawns still work.

Portal & Teleporter Protection

Claims replaces the built-in Portal, PortalReturn, and Teleporter interaction codecs with claim-aware variants (ClaimEnterPortalInteraction, ClaimReturnPortalInteraction, ClaimTeleporterInteraction). Each wraps the vanilla interaction and cancels it when the PORTAL flag is denied at the target block.

Claim Decay

The ClaimDecayTask runs on the same cadence as the rent check (rent_check_interval). Each tick it walks every player with claim data and removes all claims owned by players whose lastSeenTime is older than claim_decay_time. Online players and the server pseudo-player are skipped. Decay is disabled when claim_decay_time is empty or 0.

Plugin Imports

Servers migrating from another claims plugin can use /claim import <source> to pull claims, members, and claimed chunks into QuestLines Claims. Imports append to existing QL data — no existing claims are modified or deleted. Two sources are currently supported:

  • simpleclaims — reads a SimpleClaims SQLite database. Defaults to <universe>/SimpleClaims/SimpleClaims.db; override with --path=. Each SimpleClaims party maps to one or more QL claims, split per world and then into connected components so every resulting claim stays contiguous.
  • wiflowsclaims — reads a WiFlowsClaims JSON data directory. Defaults to <universe>/WiFlowsClaims/; override with --path=.
