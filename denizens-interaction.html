Denizens Plugin

Interaction & Quests

What happens when a player clicks a Denizen — running actions, opening quest dialogue, or showing a quest board — and the NPC-control actions Denizens registers with QuestLines Core.

The Interaction Block

A Denizen’s Interaction block (the editor’s Interaction tab) decides its click behavior.

KeyTypeDefaultNotes
ModeenumNONEClick behavior (below).
Actionsstring[][]Core action strings run in CLICK_TO_ACTION mode.
Questsstring[][]Quest ids assigned to this NPC for the quest-giver / board modes.
Requirementsstring[][]Core requirement strings checked before the actions run.
CooldownSecdouble0Per-player, per-Denizen cooldown between interactions.
ReachDistancedouble8.0Max click distance.
DialoguePageIdstring—Dialogue page opened in DIALOGUE mode.

Interaction Modes

ModeOn click…
NONEClicks are ignored.
CLICK_TO_ACTIONIf Requirements pass, run Actions through Core’s ActionManager. Works for anything — giveitem:, chat:, page:, custom actions, etc.
QUEST_GIVEROpen the dialogue for the player’s first eligible quest in Quests.
QUEST_BOARDOpen a quest board listing all assigned Quests.
DIALOGUEOpen a dialogue directly at DialoguePageId.
ℹ
Anti-spam

Interactions are rate-limited by a short global per-player guard, plus the per-Denizen CooldownSec if set.

How Quest Sync Works

The quest-related modes need QuestLines Core. When a Denizen spawns, Denizens pushes its mode and quest list into Core’s NpcConfig — keyed by the native entity UUID, not the Denizen’s own id. Core’s standard NPC interaction listener then routes player clicks to the right quest dialogue or board UI, exactly as it would for any other NPC. Setting QUEST_BOARD mode also sets the board flag on the NpcConfig entry.

ℹ
No Core? Fail-open

Without Core installed, QUEST_GIVER / QUEST_BOARD / CLICK_TO_ACTION become silent no-ops — the Denizen still spawns, moves, and renders. Add Core and the integration wires itself in automatically. 

// Make a Denizen a quest-giver for two quests
"Interaction": {
  "Mode":   "QUEST_GIVER",
  "Quests": [ "intro_quest", "daily_bounty" ]
}

NPC-Control Actions

When Core is present, Denizens registers actions with Core’s ActionManager so any quest, dialogue response, or load action can drive a Denizen at runtime. Each takes a Denizen reference (name, full UUID, UUID prefix, or #shortId) as its first argument. They are silent no-ops if Core is absent or the Denizen is unknown.

ActionEffect
setAttitudeP:<denizen>:<attitude>[:durationSec]Temporarily override the Denizen’s attitude toward the triggering player. Default duration 60s. Attitude is a schema name (PASSIVE/NEUTRAL/AGGRESSIVE/HOSTILE) or a native name (IGNORE/FRIENDLY/REVERED).
swapRole:<denizen>:<roleName>[:keepAppearance]Permanently swap the Denizen’s role. keepAppearance defaults to true (no visual flicker).
lookAt:<denizen>:<mode>[:rangeOrYaw]Set look-at mode live (OFF / NEAREST_PLAYER:range / FIXED_YAW:degrees). Applies without a respawn.
playAnim:<denizen>:<slot>:<animationId>Play an animation on a slot (Movement/Status/Action/Face/Emote).
clearAnim:<denizen>:<slot>Clear the animation on a slot.
freezePatrol:<denizen>Hold the Denizen’s patrol in place (persisted).
resumePatrol:<denizen>Release a held patrol.
 
// A quest response that turns a guard hostile to the player for 30s and plays a taunt
"Actions": [
  "setAttitudeP:Camp Warlord:HOSTILE:30",
  "playAnim:Camp Warlord:Emote:taunt"
]

These same actions can be reached programmatically through the developer API.
