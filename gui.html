GUI Plugin

QuestLines GUI

Build custom in-game screens as declarative .gui.html files written in Hytale’s native HyUIML markup. Sprinkle a handful of data-ql-* attributes on any element to wire it into QuestLines Core — hide elements by requirement, execute actions on click, and substitute text variables anywhere.

What It Is

QuestLines GUI lets server admins build custom in-game UI screens using the same HyUIML syntax Hytale uses internally for its own UIs. Each screen is a single .gui.html file in mods/QuestLinesGUI/guis/. The plugin loads these at startup and exposes them via the /qlgui command, the opengui: Core action, and optional per-GUI alias commands.

At open time the plugin processes the raw HyUIML per-player: it removes elements whose data-ql-req requirements fail, substitutes Core text variables ({player}, {track:id}, etc.) throughout the markup, wires up event listeners for buttons, item slots, checkboxes, and dropdowns, and finally hands the cleaned HyUIML to the Hytale UI renderer.

ℹ
Optional Core dependency

QuestLines GUI fails open if Core is missing: requirements pass, actions no-op, and text is returned unchanged. The opengui: action is only registered when Core is present.

Web Editor

The recommended way to build GUIs is the online point-and-click editor at evilcraft.net/GUIEditor. Build the screen visually, then export a .gui.html file and drop it into mods/QuestLinesGUI/guis/. The editor also imports existing .gui.html files for editing.

Run /qlgui editor in-game to get the link sent to chat as a clickable URL. After importing a file on disk (or editing one by hand), run /qlgui reload to pick up the changes without restarting the server.

File Format

Each file in mods/QuestLinesGUI/guis/ named <id>.gui.html defines one screen. The id is taken from the filename stem; an explicit data-ql-id on the outermost container overrides it.

A GUI is a single HyUIML document with a <div class="container"> at the root and a <div class="container-contents"> wrapper inside. All QuestLines-specific metadata goes on the root container via data-ql-* attributes. 

<!-- mods/QuestLinesGUI/guis/blacksmith.gui.html -->
<div class="container"
     data-hyui-title="Aldric's Forge"
     style="anchor-width: 480; anchor-height: 420;"
     data-ql-id="blacksmith"
     data-ql-command="shop"
     data-ql-close="false"
     data-ql-refresh="true">
  <div class="container-contents">
    <div style="layout-mode: TopScrolling;">
      <!-- elements go here -->
    </div>
  </div>
</div>

Root container data-ql-* attributes

AttributeDefaultDescription
data-ql-idfilename stemGUI id used by opengui:<id> and /qlgui open.
data-ql-commandnoneOptional alias command. If set, /<command> is registered on startup and opens the GUI for the player who runs it.
data-ql-closefalseDefault close-on-click for every interactive element. Individual elements may override.
data-ql-refreshtrueDefault refresh (re-render after action) for every interactive element. Individual elements may override.
ℹ
HyUIML is Hytale’s native markup

This plugin does not invent a new UI language. Standard HyUIML features — layout-mode, anchor-width, flex-weight, font-bold, horizontal-align, CSS classes like container / container-contents / small-secondary-button, and every built-in element (<label>, <button>, <progress>, <sprite>, etc.) — all work as documented by Hytale. QuestLines only adds the data-ql-* attributes described below.

data-ql Attributes

All QuestLines hooks are data-ql-* attributes. Pipe (|) is the separator for lists of requirements or actions. Attributes apply to any element unless noted otherwise — you can hide a whole <sprite> with data-ql-req, or put data-ql-actions on an <option> inside a dropdown.

AttributeApplies toDescription
data-ql-req Any element Pipe-separated list of Core requirements. If any fails, the entire element (and its subtree) is removed before render.
data-ql-actions <button>, .item-grid-slot, <option> Pipe-separated list of Core actions fired on click / value change.
data-ql-close Root container + interactive elements Override the GUI-level close-on-click default for this element.
data-ql-refresh Root container + interactive elements Override the GUI-level refresh default for this element.
data-ql-click-req .item-grid-slot Click-time requirements. If any fail, the click is silently blocked but the slot remains visible. If set, the slot gets a green (passing) or red (failing) background tint.
data-ql-check-req <input type="checkbox"> Determines the initial checked state at render time.
data-ql-check-actions <input type="checkbox"> Actions fired when the player toggles the box on.
data-ql-uncheck-actions <input type="checkbox"> Actions fired when the player toggles the box off.
data-ql-label <input type="checkbox"> Text rendered next to the checkbox.

Click flow: close vs refresh

After an interactive element fires its actions, the plugin decides what to do next:

  • If the resolved close is true, the GUI is closed.
  • Otherwise, if the resolved refresh is true, the GUI is re-opened for the same player — re-evaluating all data-ql-req, re-substituting text variables, and re-applying slot click-req tints.
  • Otherwise, the GUI stays open as-is.

Resolution precedence is element override → GUI default. For dropdowns, precedence is option → select → GUI default.

Interactive Elements

Four element kinds are “live” — the plugin registers an event listener on each and fires Core actions when the player interacts. Every listener runs on the world thread, so actions that mutate world state are safe.

Button

Any <button> with data-ql-actions becomes clickable. Buttons with class="disabled" are skipped. 

<button class="primary"
        data-ql-req="economy:canafford:10"
        data-ql-actions="economy:take:10|item:iron_sword:1|message:Bought!"
        data-ql-close="true">Buy Iron Sword (10g)</button>

Item Grid

An inventory-style grid. Use <div class="item-grid"> as the container and <div class="item-grid-slot"> for each slot. Hytale attributes data-hyui-slots-per-row, data-hyui-item-id, data-hyui-quantity, data-hyui-name, and data-hyui-description control rendering; QuestLines adds data-ql-req, data-ql-actions, and data-ql-click-req per slot. 

<div class="item-grid" data-hyui-slots-per-row="5">
  <div class="item-grid-slot"
       data-hyui-item-id="iron_sword"
       data-hyui-quantity="1"
       data-hyui-name="Iron Sword"
       data-hyui-description="A sturdy blade. 10g."
       data-ql-click-req="economy:canafford:10"
       data-ql-actions="economy:take:10|item:iron_sword:1"></div>
</div>

When a slot has data-ql-click-req, the plugin paints the slot background green (click allowed) or red (click blocked) so players see at a glance what’s affordable. Without data-ql-click-req, no tint is applied.

Checkbox

A checkbox is an <input type="checkbox">. Initial state comes from data-ql-check-req; clicking fires data-ql-check-actions when toggling on, or data-ql-uncheck-actions when toggling off. The label next to the box comes from data-ql-label. 

<input type="checkbox"
       data-ql-label="Show quest notifications"
       data-ql-check-req="hasTag:notif_on"
       data-ql-check-actions="addTag:notif_on"
       data-ql-uncheck-actions="removeTag:notif_on" />

Dropdown

A <select> with one or more <option> children. Each option may have its own data-ql-actions; when the player changes the selection to a given option, those actions fire. Options may also have data-ql-req to hide themselves, and their own data-ql-close / data-ql-refresh overrides. 

<select data-ql-close="false" data-ql-refresh="true">
  <option value="peaceful" data-ql-actions="setVariable:difficulty:peaceful">Peaceful</option>
  <option value="hard"     data-ql-actions="setVariable:difficulty:hard">Hard</option>
  <option value="nightmare" data-ql-req="hasTag:beaten_game"
                                data-ql-actions="setVariable:difficulty:nightmare">Nightmare</option>
</select>

Display Elements

These elements just render — they don’t fire actions. All of them accept data-ql-req to be hidden conditionally, and text variables in their text content and attributes are substituted automatically.

ElementPurpose
<label>Styled text. Use style for font-size, color, font-bold, horizontal-align, etc.
<img src="...">Static image from a resource-pack path.
<sprite src="...">Animated sprite. Hytale frame attributes (data-hyui-frame-width, data-hyui-frame-height, data-hyui-frame-per-row, data-hyui-frame-count, data-hyui-fps) control playback.
<progress value="..." max="...">Progress bar. Add class="circular" and data-hyui-color="#rrggbb" for a ring-style fill.
<hyvatar username="..." render="head" size="64">Player avatar. render accepts head, body, bust, or full. Use username="{player}" for the viewing player.
<span class="item-icon" data-hyui-item-id="...">Single item icon rendered by the Hytale item renderer.
<hotkey-label input-binding-key="...">Displays the player’s bound keybind for a given input action.
<div style="layout-mode: ...">Layout panel. Use data-ql-req to hide the whole subtree.
<div style="anchor-height: N;">Spacer (fixed-height empty box).
<div style="anchor-height: N; background-color: #rrggbb;">Divider (thin coloured rule).

Core Integration

opengui: action

When both QuestLines GUI and QuestLines Core are installed, the plugin registers an opengui:<guiId> action with Core. Use it anywhere Core actions are accepted — response Actions lists, page LoadActions, buttons in other GUIs, or via the developer API. 

// Open a shop screen from a dialogue response
"opengui:blacksmith"

// Auto-open a welcome screen once (via LoadActions)
Requirements: ["questNotStarted:welcome"]
LoadActions:  ["startquest:welcome", "opengui:welcome_screen"]

Requirements on elements

Any element with data-ql-req is removed (along with its subtree) when any requirement fails. Requirements use the exact same syntax as quest page requirements — hasTag:vip, questCompleted:intro, track:killboss:5, economy:canafford:50, and everything else in the Requirements reference. 

<button class="primary"
        data-ql-req="hasTag:vip"
        data-ql-actions="opengui:vip_shop">VIP Shop</button>

Actions in buttons, slots, and dropdown options

The data-ql-actions list accepts any Core action. This includes quest actions (questCompleted:), economy actions (economy:give:500), navigation (opengui:otherId), and everything else in the Actions reference. Actions run on the world thread via Core’s executeActions API.

Text variables

Every text variable available in dialogue is also available in GUIs. The plugin walks every text node and every non-data-ql-* attribute looking for {…} substitutions, so you can drop variables into label text, button labels, image src, item ids, hyvatar usernames, progress value, tooltip fields, and anywhere else you’d expect.

Since a GUI has no dialogue-page context, page-specific variables (like {response:*}) resolve to empty strings. Player-scoped variables ({player}, {track:id}, {variable:name}, etc.) all work normally.

Commands

Root command: /qlgui. All subcommands require questlines.admin.

CommandDescription
/qlgui open <guiId> [player] Open a GUI for yourself or for a named online player. The optional player argument defaults to self.
/qlgui list List all loaded GUI ids.
/qlgui reload Reload all .gui.html files from disk. Unregisters and re-registers alias commands.
/qlgui editor Sends a clickable link to the online GUI editor in chat.

Alias commands

If a GUI’s root container has a data-ql-command attribute, the plugin registers /<commandName> as a first-class server command on startup. Running the command opens that specific GUI for the player. Alias commands are unregistered on /qlgui reload and re-registered from the fresh config.

Each alias is gated by the permission questlines.gui.<commandName>, default true. This check does not apply to /qlgui open or to the opengui: action — both bypass it so admins and quest scripts can open any GUI unconditionally.

Permissions

PermissionDefaultDescription
questlines.admin false Required for every /qlgui subcommand.
questlines.gui.<commandName> true Gates each dynamically registered alias command. Revoke it on specific players or groups to restrict access without removing the GUI itself.

Data Directory

GUI definitions live in mods/QuestLinesGUI/guis/. Each file is named <guiId>.gui.html and contains raw HyUIML. The plugin scans the directory at startup and on /qlgui reload.

Legacy .gui.json files from older versions are ignored with a one-time warning — import them into the web editor to convert them to the HyUIML format, then re-export as .gui.html.

Full Example

A simple shop screen with a VIP-only section, a progress bar, and a VIP toggle:

<!-- mods/QuestLinesGUI/guis/blacksmith.gui.html -->
<div class="container"
     data-hyui-title="Aldric's Forge"
     style="anchor-width: 420; anchor-height: 420;"
     data-ql-id="blacksmith"
     data-ql-command="shop"
     data-ql-close="false"
     data-ql-refresh="true">
  <div class="container-contents">
    <div style="layout-mode: TopScrolling; padding: 12;">

      <label style="font-size: 18; color: #e8c97a; font-bold: true; horizontal-align: Center;">
        Welcome, {player}!
      </label>

      <div style="anchor-height: 1; background-color: #444444;"></div>

      <label style="font-size: 13; color: #aabbcc;">
        Smith reputation: {track:smith_rep} / 100
      </label>
      <progress value="{track:smith_rep}" max="100"
                style="anchor-width: 380; anchor-height: 20;"
                data-hyui-color="#e08040"></progress>

      <div style="anchor-height: 8;"></div>

      <button class="primary"
              data-ql-req="economy:canafford:10"
              data-ql-actions="economy:take:10|item:iron_sword:1|message:Bought an iron sword.">
        Buy Iron Sword (10g)
      </button>

      <button class="primary"
              data-ql-req="hasTag:vip|economy:canafford:500"
              data-ql-actions="economy:take:500|item:legendary_blade:1">
        Buy Legendary Blade (VIP -- 500g)
      </button>

      <input type="checkbox"
             data-ql-label="Remind me of daily smith quests"
             data-ql-check-req="hasTag:smith_reminders"
             data-ql-check-actions="addTag:smith_reminders"
             data-ql-uncheck-actions="removeTag:smith_reminders" />

      <button class="small-secondary-button"
              data-ql-close="true"
              data-ql-actions="">Close</button>

    </div>
  </div>
</div>

With data-ql-command="shop" on the container, players can open this screen with /shop (or admins can call /qlgui open blacksmith, or a quest response can fire opengui:blacksmith).
