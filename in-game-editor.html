Getting Started

In-Game Editor Walkthrough

Build a quest end-to-end without ever leaving the game. The in-game editor (/ql quest) covers everything: quests, pages, responses, requirements, actions, NPC assignment, macros, achievements, and events. This page walks you through making your first quest step-by-step.

Opening the Editor

Run /ql quest in chat (aliases: /ql q, /ql ui, /ql create). The editor opens to the last tab you used; first-time users land on the EDITOR tab.

You need the questlines.admin permission to use it. All editor changes autosave to disk immediately — there is no global "Save" button.

ℹ
Six top tabs

EDITOR — quests + pages + responses
USERS — per-player state, tags, trackers, quest grants
NPCS — link quests to NPCs
MACROS — reusable requirement / action bundles
ACHIEVEMENTS — server-defined milestones
EVENTS — server-lifecycle action triggers

The ? HELP button in the title bar opens the in-game reference panel — the most up-to-date listing of every requirement, action, tracker type, objective syntax, and dialog variable.

Your First Quest, Step-by-Step

We'll build a simple kill quest: "Bandit Patrol — talk to the Guard Captain, kill 5 Zombies, return for a reward."

  1. 1. Open the editor and pick the EDITOR tab.

    /ql quest. The EDITOR tab is selected by default. The left sidebar has three section buttons — QUEST, PAGE, RESPONSES — plus the Pages list.

  2. 2. Create a new quest from the Quest dropdown.

    At the top of the editor, the Quest dropdown is searchable. Type a brand-new ID (lowercase + underscores, e.g. bandit_patrol) and press Enter. The dropdown autocreates the entry as soon as you begin filling fields below.

  3. 3. Fill out the QUEST section.

    Click QUEST in the left sidebar to make sure the section is visible. Fill:

    • Quest ID — bandit_patrol (matches the filename)
    • Quest Title — Bandit Patrol
    • Description — short journal summary
    • Rewards — display-only string ("1 Iron Sword + 100g")
    • Repeatable — leave unchecked for a one-off quest
    • Requirements — leave EMPTY. (Top-level requirements are a hard gate that hides the entire quest from every player who fails the check. Conditional gates belong on individual pages, not here.)
    • Load Actions / Actions — leave empty. Top-level Actions fire on quest completion, not acceptance.
  4. 4. Add your pages.

    The Pages list sits below the section buttons in the left sidebar. Click + three times to create three pages. Use the /\ and \/ arrows to reorder, the X to delete, and click a page row to edit it.

    Name your pages in the Page ID field on the right (e.g. finished, complete, progress, intro). Order matters — see step 9.

  5. 5. Fill out each page's PAGE section.

    Click a page in the Pages list, then click PAGE in the left sidebar. For each page set:

    • Page ID — must be unique within the quest
    • NPC Name — display name shown above the dialogue text (Guard Captain)
    • Dialog — the NPC's spoken text. Supports inline variables like {username}, {track:zombie_kills}, and formatting tags like {b}…{/}, {#FF8800}…{/}.
    • Journal Text — what the player sees when they open the quest in their journal
    • Requirements — see step 9 for the layered order
    • Load Actions — fire every time this page is shown
    • Objectives — live HUD/journal progress bars; one entry per goal (e.g. track:zombie_kills:5). Append ::Custom Label to override the auto-generated text. Use text:Find the cave for static lines that don't track progress.
  6. 6. Add responses on the intro page.

    With the intro page selected, click RESPONSES in the left sidebar. Use + / - to add or remove a response. There is no limit on response count — empty Text hides a response.

    For each response set:

    • Text — button label ("Accept" / "Not interested")
    • Requirements — must all pass for the button to show
    • Actions — run in order when clicked

    On the "Accept" response, add these Actions via the + on the Actions field:

    • startquest:bandit_patrol — marks the quest started
    • track:zombie_kills:kill:Zombie — creates the named tracker

    On the "Claim Reward" response of the completion page:

    • completequest:bandit_patrol — marks the quest complete
    • untrack:zombie_kills — clears the tracker
    • item:Weapon_Sword_Iron:1 — gives the reward
  7. 7. Use the Add Entry builder for requirements and actions.

    Clicking + on any Requirements or Actions field opens the Add Entry overlay. Pick a Type from the searchable dropdown (~50 types — kill, track, item, hasTag, cooldown, timeOfDay, economy, …). The Param 1/2/3 fields reshape themselves to match the selected type and offer autocomplete from baked catalogs (every entity ID, item ID, page ID, quest ID, macro ID).

    Click Insert to add the entry; Cancel to back out.

  8. 8. Assign the quest to an NPC.

    Switch to the NPCS tab. Pick the NPC in the main dropdown (the list includes both HyCitizens NPCs and standard Hytale entities — the entries are populated from npcs.json). Open the QUESTS section in the sidebar, pick bandit_patrol in the Quest dropdown, and click ADD. REMOVE unassigns; EDIT jumps back to the EDITOR tab with that quest loaded.

    Shortcut: close the editor, run /ql wand bandit_patrol, then punch the NPC. The wand reads its citizen ID (or entity UUID) and writes the assignment instantly. Cancel with /ql wandcancel.

  9. 9. Double-check page order.

    Page resolution is top-to-bottom: first match wins. The page with the most restrictive Requirements goes FIRST, the catch-all intro page goes LAST. For this quest the correct order is:

    • finished — Requirements: questCompleted:bandit_patrol
    • complete — Requirements: questStarted:bandit_patrol, track:zombie_kills:5
    • progress — Requirements: questStarted:bandit_patrol
    • intro — Requirements: questNotStarted:bandit_patrol

    If you put intro first, every player who hasn't started the quest will see it forever — including players in progress.

  10. 10. Test it.

    Close the editor and talk to the NPC. Accept the quest, kill some Zombies (watch the HUD objective tick up), and return for the reward. If something doesn't behave the way you expected, run /ql validate for a non-destructive lint pass — it reports unreachable pages, unknown requirements, missing trackers, etc. without reloading.

Where Things Get Saved

The editor autosaves on every field change. There is no Save button. Files written:

  • QuestLines/quests/<questId>.json — one file per quest with all pages embedded under PageData
  • QuestLines/npcs.json — NPC-to-quest assignments
  • QuestLines/macros/<macroId>.json — macro definitions
  • QuestLines/achievements/<achievementId>.json — achievements
  • QuestLines/events.json — event-triggered action lists
  • QuestLines/players.json — per-player state (auto-managed)

Quest validation runs automatically on plugin start and on /ql reload. /ql validate runs the same checks on demand without reloading.

Quality-of-Life Features

  • Searchable dropdowns everywhere. Every Quest / Page / NPC / Type dropdown supports inline search — start typing to filter.
  • Wand mode. /ql wand <questId> + punch NPC skips the NPCS tab entirely. /ql wandcancel to abort.
  • Sticky state. The editor remembers your last tab, selected quest, selected page, and selected response between sessions.
  • Help panel. The ? HELP button in the title bar is the single most-authoritative reference for every action / requirement / tracker type / variable / formatting tag the plugin supports.
  • Translate Quest. In the QUEST section, the Translate Quest button auto-fills missing locale strings via the configured translation backend (MyMemory by default; can be swapped to self-hosted LibreTranslate or disabled in config.yml).
  • Per-response styling. The RESPONSES section's right column lets you customise Portrait Override, Portrait Side, Dialog Width, Response Mode (buttons vs continue prompt), Auto Trigger, Requires Response, and per-button colour / icon.

Admin Operations from the Console

Some operations are quicker from chat than from the editor:

  • /ql reload — reload all configs from disk (use on the second server in a network after editing on the first)
  • /ql validate — lint all quest configs without reloading
  • /ql list — list every quest ID and title
  • /ql remove <questId> — delete a quest (run twice within 30s to confirm)
  • /ql wand <questId> — assign a quest to an NPC by punching it
  • /ql action startquest:<questId> --player=<name> — force-start a quest on a player (works with any action — completequest:, addTag:, etc.)
  • /ql requirement <value> --player=<name> — test a requirement and print PASS or FAIL
  • /ql player reset <player> <field> — reset a player's tags, completed, started, progress, timestamps, variables, stringvars, tracked, trackers, questitems, markers, blockoverrides, achievements, iconoverrides, escorts, journal, or all (escorts despawns live NPC clones; blockoverrides repaints real blocks for online players)
  • /ql achievement grant|revoke|reset <player> <achievementId> — adjust achievements

Pair the editor with the AI tools
