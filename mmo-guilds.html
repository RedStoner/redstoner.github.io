Guilds & Halls

Long-lived player organisations with four ranks, a permission matrix, a shared treasury and tabbed chest — plus per-guild instanced halls in PREFAB or BUILD mode.

Guilds

Guilds are persistent player organisations with a name, a short tag (the abbreviation shown in chat), a message-of-the-day, a member roster, a shared treasury, a shared chest, and a guild hall.

Ranks

Every guild has four hard-coded ranks, in strict order from highest to lowest:

  • OWNER — one per guild. Has every permission unconditionally.
  • OFFICER — configurable trusted rank.
  • MEMBER — default rank for new joiners.
  • RECRUIT — lowest rank for probation/trial members.

/guild promote and /guild demote shift a member one step at a time and can only be run by the owner. /guild transfer <player> hands the OWNER rank to another member; the previous owner is demoted to OFFICER.

Permissions

Each rank has a default permission set, and individual players can have overrides that grant or revoke specific permissions on top of their rank’s defaults. The owner always has every permission regardless of overrides.

Permission Grants
BUILDPlace and break blocks inside the guild hall (BUILD-mode halls only; permission-gated).
CHEST_VIEWOpen the guild chest UI.
CHEST_DEPOSITMove items into a guild chest section.
CHEST_WITHDRAWMove items out of a guild chest section.
INVITEInvite outsiders to the guild.
KICKRemove members from the guild (cannot kick equal or higher rank).
PROMOTERaise another member by one rank (owner-only by default).
DEMOTELower another member by one rank (owner-only by default).
SET_MOTDChange the guild’s message of the day.
MANAGE_HALLSet the guild hall spawn, run upgrades, and toggle hall settings.
MANAGE_PLOTSDefine and delete rent/sale plots inside the guild hall.
MANAGE_CLAIMSAdd and remove guild chunk claims (requires QuestLines Claims).
VISIT_OPENAllow non-members to visit the guild hall via /guild hall visit.

The owner edits the permission matrix from the Guild Permissions UI (opened from /guild ui or via /guild perms set). Per-player overrides can also be set with /guild perms player <player> <perm> --value=true|false.

Treasury

Each guild has a single shared currency balance. Members can deposit with /guild bank <amount> (gated on the questlinesmmo.guild.bank.deposit permission and a guild_bank feature flag in the guild hall’s upgrade level). Withdrawals are done via the Treasury tab in the guild UI. Admins adjust treasury balances directly with /qlmmo admin guild currency.

Guild Chest

The guild chest is a multi-section shared inventory. Each section is a grid of slots (default 54 slots per section, matching a Hytale double chest). The maximum number of sections is set per upgrade tier by maxChestSections in config.guildHall.upgradeLevels (BUILD mode) or by the active template tier (PREFAB mode). Members open the chest with /guild chest if they have CHEST_VIEW and move items in or out subject to CHEST_DEPOSIT and CHEST_WITHDRAW.

Guild Halls

Every guild has its own instanced world named guildhall_<guildId>. The hall is loaded on demand when a member runs /guild home, stays alive while at least one player is inside, and unloads after a configurable idle grace period (config.guildHall.unloadGraceMinutes, default 5).

A new guild’s first /guild home opens a two-step creation carousel: the owner picks a biome (the world seed and generator type) and then a template (the structure that gets pasted at the biome’s configured spawn point). Both are immutable after creation.

PREFAB vs BUILD

Guild halls run in one of two server-wide modes set in config.guildHall.mode. The mode applies to every hall on the server and is decided once when the plugin is configured.

Mode Block editing Upgrade ladder
PREFAB No manual block editing ever. The hall listener cancels every player block place and break in the hall world. Per-template upgrade tiers. Each tier names a structure prefab to paste over the world; running /guild hall upgrade confirm deducts the tier’s cost from the guild treasury and re-pastes the structure.
BUILD Free building inside guild-claimed chunks (or, with QuestLines Claims installed, inside the guild’s claim region). Wilderness inside the hall world can be locked down via config.guildHall.wildernessProtectedInBuild. Global upgrade levels defined in config.guildHall.upgradeLevels. Levels unlock mechanical perks (chest sections, slots per section, member cap, plots, feature flags). They never paste blocks.

Spawn Point

The spawn point is where /guild home drops players. It defaults to the template’s spawnOffset applied to the biome’s buildingSpawn. Members with the MANAGE_HALL permission can run /guild hall setspawn while standing where they want the new spawn.

Visiting Other Halls

/guild hall visit <guildName> teleports the player into another guild’s hall, but only if that guild has granted the VISIT_OPEN permission to the appropriate rank (typically RECRUIT or below). Visitors are gated by the same listener rules as members: PREFAB halls block all editing, BUILD halls follow the hall’s claim and plot rules.

Plots (Guild Halls)

Players with the MANAGE_PLOTS permission can carve up the guild hall into rent or sale plots. Plot definition uses the standard /claim wand selection workflow (requires QuestLines Claims):

  1. Run /claim wand to receive the Claim Staff.
  2. Click two corners to define the plot volume.
  3. Run /guild hall plot rent <name> <price> <days> for a leased plot, or /guild hall plot buy <name> <price> for a one-time-purchase plot.

/guild hall plot list prints the guild’s defined plots and /guild hall plot delete <plotId> removes one. Plots are stored separately from admin Claims rent/buy regions and never appear in the global /claim rentbuy browser unless explicitly configured to. Guild plots also intentionally do not support prefab saving — that workflow is reserved for admin regions.

Claims Integration

When QuestLines Claims is installed, the bridge in net.evilcraft.questlinesmmo.bridge.ClaimsBridge hooks the hall world into the Claims protection chain. Members of the guild are treated as members of the hall’s region; the config.guildHall.maxClaimsPerGuild setting caps how many chunks a single guild can hold inside the hall. Without Claims installed the bridge is a no-op and GuildHallListener falls back to a simple build-permission gate.
