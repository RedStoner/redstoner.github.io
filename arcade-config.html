Arcade Plugin

Configuration

Engine-wide tunables live in config.json; per-game tunables live in configs/<gameId>.json. Files are created on first start with default values and merged with defaults on load — missing keys are silently filled in, so old configs keep working after an upgrade.

Engine Config (config.json)

Lives at mods/QuestLinesArcade/config.json. Created on first start; keys missing from disk fall back to the defaults below.

Per-Game Configs (configs/<gameId>.json)

Each pack registers its own configs at startup. Files are written on first plugin start; missing keys are filled with the registered defaults on every reload, so adding new fields in an upgrade does not reset your settings.

★
Slot multipliers are not in the config

Three-of-a-kind multipliers for the slot machine are baked into the Symbol enum and cannot be tuned without recompiling — cherry 5×, silver 10×, gold 20×, ruby 50×, emerald 100×, diamond 500×. The config only controls the bet size and the consolation “any two cherries” payout.

Puzzle Pack configs

The Puzzle Pack registers no per-game JSON configs. Word Search, Crosswords, Lights Out, Nonograms, and Kakuro all draw from bundled puzzle banks under each game’s resources directory. Adding configurable difficulty would mean writing a new *Config record and registering it in PuzzlePackPlugin.setup().

Reloading and Safety

  • How to reload: there is no live reload command. Restart the plugin (or the server) to pick up edits.
  • Merging: every config is decoded by walking the record components and pulling each field from JSON, falling back to the registered default. Adding a new field in a plugin upgrade is safe — old files just inherit the new default on next load.
  • Parse errors: a malformed JSON file is left in place and the registered defaults are used at runtime. Fix the file and restart.
  • Writes: profile and archive writes go through an atomic temp-file-then-rename. Config writes are simpler — they happen only once at startup if the file is missing.
