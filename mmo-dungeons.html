Dungeons & LFG

Instanced PvE encounters with checkpoints, boss phases, and timed objectives — plus the Looking-For-Group browser that fills them.

Dungeons

Dungeons are instanced PvE encounters defined as JSON files under mods/QuestLinesMMO/dungeons/. Each definition names a world template, an instance spawn point, a recommended level, a list of objective IDs, an optional list of boss phases keyed to HP thresholds, and a completion reward.

Entering an Instance

The party leader runs /dungeon enter <dungeonId>. The manager validates that the leader is in a party of at least one and at most maxPartySize members, copies the dungeon’s world template into a fresh world named dungeon_<dungeonId>_<uuid>, and teleports every online member to the instance spawn. Offline party members are not pulled in.

Member State

Each player in an instance has one of three states — ALIVE, DEAD, or DISCONNECTED — tracked by the instance. Death and disconnect both pause the player’s active participation, but they behave differently:

  • Death — opens the Checkpoint UI with a respawn countdown (config.dungeon.respawnDelaySeconds, default 3). Respawning teleports back to the instance’s last activated checkpoint, or the instance spawn if none.
  • Disconnect — the instance starts a rejoin grace timer of config.dungeon.rejoinGraceSeconds seconds (default 300). Reconnecting within that window restores the player to the instance at the last checkpoint.

A wipe (every member DEAD or DISCONNECTED) flags the instance for cleanup after config.dungeon.postCompleteCleanupSeconds seconds and teleports any remaining members out.

Boss Phases

A dungeon definition may declare an ordered list of boss phases, each with an HP threshold (a fraction between 1.0 and 0.0) and a list of ability IDs the boss should use during that phase. The BossPhaseController watches the boss entity’s HP during combat and advances phases as thresholds are crossed.

Timed Objectives

Objectives can be timed: a script (or another listener) starts a TimedObjective with a timeout and a callback. The Dungeon HUD shows the countdown for every active timed objective in the instance. Failing to complete in time fires the failure callback and typically ends the run.

Completion

When all required objectives are completed, the instance moves to the COMPLETED state and grants the dungeon’s completionReward (XP, currency, guild currency, items) to every still-alive member. After postCompleteCleanupSeconds the instance world is unloaded and deleted.

LFG Browser

The Looking-For-Group browser lets parties advertise that they need additional players for a piece of content (a dungeon ID or a world-event ID). Listings have a TTL, default config.lfg.listingTtlMinutes = 30; expired listings are pruned every config.lfg.listingExpiryCheckIntervalSeconds seconds.

Run /lfg to open the browser. Every action lives in the UI:

  • Create Listing — click the button on the top-right of the browser when you don’t already have a listing. Pick content from the paginated list (dungeons + events), type an optional description, toggle which roles you need (ANY, TANK, HEALER, DPS), and press Post Listing.
  • Browse — the list view shows up to six listings per page with < / > pagination. Use the role filter row at the top and the search field to narrow results.
  • Join — click any listing row to open it, then pick a role button (Join as Tank, Join as Healer, Join as DPS, or Join for any role).
  • Manage your listing — the Manage My Listing button (replaces Create Listing while you have one active) opens your own listing’s detail view. Accept or decline incoming join requests, or press Cancel Listing to remove it.
