Denizens Plugin

Runtime API

Spawn, clone, instruct, and react to Denizens at runtime — the API QuestLines Core uses to drive NPCs, and the surface any plugin can call to move an NPC, set its state, or listen for its death.

Overview

Beyond the identity and quest-assignment helpers on the Migration & API page, Denizens exposes a full runtime-control surface: clone an NPC, walk it somewhere, change its health or attitude, hide it, read its live position, and subscribe to lifecycle events. Everything is reachable through the same reflection-resolved DenizensAPI object — no compile-time dependency on Denizens.

QuestLines Core consumes this through a single routing helper, NpcControl, whose policy is prefer Denizens → fall back to HyCitizens → no-op. That is why every NPC quest action (move, patrol, attitude, equip, hide, escort, …) now works on a Denizen with no HyCitizens installed, and still works on a HyCitizens citizen when only that plugin is present. The same id verbs route to whichever provider owns the id.

ℹ
Two audiences

Quest authors never call this directly — you use the actions below and Core routes them. Plugin developers call DenizensAPI methods reflectively for direct control.

Quest Actions (provider-agnostic)

These quest actions route through NpcControl. Each takes an NPC id (a Denizen name / short id #N / UUID, or a HyCitizens citizen id) and acts on whichever provider owns it. See the Actions reference for full argument formats.

ActionEffect
spawnCitizen: / spawnDenizen:Clone a template by name into an ephemeral, auto-cleaned instance.
moveCitizen: / stopCitizen:Walk the NPC to coords (pathfinding, not teleport) / halt it.
patrol: / stopPatrol:Run / stop the NPC’s patrol.
setAttitude: / setHealth: / setInvulnerable: / setEquip:Live state changes.
hideCitizen: / hideNametag:Global hide of the body / nametag.
hideNpc: / showNpc:Per-player hide (only the calling player).
moveGroup: / patrolGroup: / stopGroup: / stopPatrolGroup:Act on every group member (a Denizen Tag or a HyCitizens group).
startEscort: & the escort* familySpawn a private follower clone and drive it.
ℹ
spawnDenizen alias

spawnDenizen: is an alias of spawnCitizen: with identical behaviour — a clearer name when authoring against Denizens. Both clone a Denizen template (a Denizen carrying that name) into an ephemeral clone.

Resolving the API

Resolve the API once, reflectively, then invoke methods on it. Signatures use only primitives, String, UUID, and Hytale server types (PlayerRef, Ref<EntityStore>) plus JDK functional interfaces, so nothing from the Denizens classloader has to cross into yours. 

PluginBase denizens = HytaleServer.get().getPluginManager().getPlugin(
        new PluginIdentifier("net.evilcraft", "QuestLinesDenizens"));
Object api = denizens.getClass().getMethod("getApi").invoke(denizens);

// e.g. walk Denizen #4 to a point
UUID id = (UUID) api.getClass()
        .getMethod("findByShortId", int.class).invoke(api, 4); // Optional<UUID> in practice
api.getClass().getMethod("moveTo",
        UUID.class, double.class, double.class, double.class)
        .invoke(api, id, x, y, z);

Write operations are non-blocking — native work is dispatched to the right world thread internally. Most return boolean: true when the action was scheduled, false when the Denizen is unknown or required state is missing.

Spawning & Cloning

cloneEphemeral(sourceNameOrId, world, x, y, z) deep-copies an existing Denizen (the “template”) into a fresh instance and returns its new id. The clone is ephemeral:

PropertyBehaviour
Not persistedNever written to disk — gone after a server restart.
Not reconciledThe spawn reconciler ignores it; its lifecycle is managed by whoever spawned it.
Auto-deleted on deathDies once and is removed (never respawns), regardless of the template’s RespawnOnDeath.
Inherits the templateRole, appearance, behavior, scale, and combat flags (incl. Invulnerable) all copy from the source.

Use removeDenizen(id) to delete any Denizen outright (despawn + drop from the registry + delete its file; a no-op file delete for ephemerals). This is the spawnCitizen: / escort building block.

⚠
Killable clones need a killable template

Denizens default to Invulnerable: true. If a clone is meant to be killed (e.g. a killcitizen objective), make the template’s combat block vulnerable — the clone inherits it.

Instructing Movement

Movement commands drive the NPC’s native pathfinder — the Denizen walks and routes around obstacles. (This is distinct from move, which teleports.)

MethodEffect
moveTo(id, x, y, z)Walk to the point, then stand there on arrival.
startPatrol(id)Run the Denizen’s own configured patrol waypoints (ignores the Enabled flag).
stopMovement(id)Halt in place, cancelling an active move/patrol command.
isPatrolling(id)Whether it is patrolling right now.
getActivePatrolPath(id)Synthetic path name ("patrol" while patrolling, else null).
getLivePosition(id)Live [x, y, z], or null if not currently ticking. Non-blocking (per-tick cache).

A command takes precedence over the Denizen’s configured behavior (schedule, guard, patrol, wander) until cleared, and applies on the next tick — there is no warm-up delay. This is what lets escort followers respond to escortMove: instantly.

setAttitude(id, name)Base attitude (PASSIVE / NEUTRAL / AGGRESSIVE / HOSTILE), pushed to nearby players immediately.
setEquipment(id, slot, itemId, qty)Set an equipment slot (head/chest/hands/legs/mainhand/offhand).

ℹ
No live damage knob

setDamage is a no-op on Denizens — native NPC damage comes from the equipped weapon, not a stat. Give the Denizen a weapon with setEquipment (the setEquip: action) instead. On a HyCitizens citizen, setDamage still applies.

Groups

A Denizen “group” is simply a Tag. idsWithTag(tag) returns every Denizen id carrying that tag; callers compose group operations by looping the single-id methods. Core’s group actions act on the union of Denizens carrying the tag and HyCitizens members of the same-named group.

Lifecycle Events

Subscribe to Denizen lifecycle with typed callbacks. Payloads carry only a UUID (the Denizen id) and, where relevant, a PlayerRef — both shared server-classloader types — and the listener types are JDK BiConsumer / Consumer, so a lambda from your plugin passes straight in.

MethodFires with
addDeathListener(BiConsumer<UUID, PlayerRef>)(denizenId, killer) — killer is null for environmental/unknown deaths. Fires before any respawn is scheduled.
addInteractListener(BiConsumer<UUID, PlayerRef>)(denizenId, player) on every player click.
addSpawnListener(Consumer<UUID>)(denizenId) when the live entity is (re)spawned.
addDespawnListener(Consumer<UUID>)(denizenId) on explicit despawn (not death).
 
// Credit a quest kill when a player kills any Denizen
api.getClass().getMethod("addDeathListener", BiConsumer.class).invoke(api,
    (BiConsumer<UUID, PlayerRef>) (denizenId, killer) -> {
        if (killer != null) creditKill(killer, denizenId);
    });
⚠
Threading

Listeners fire on the world thread that raised the event. Keep handlers fast and thread-aware, and never throw — a thrown listener is logged and skipped, but it won’t be retried.

Limitations

Escort pause-on-clickClicking a Denizen escort follower does not pause it (this is wired for HyCitizens clones only).
