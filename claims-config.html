Claims Plugin

Config & Permissions

Plugin settings and database connection, the permission nodes, server-wide permission groups, and the on-disk file layout.

Configuration

All plugin-level settings live in mods/QuestLinesClaims/questlinesclaims.conf. Missing keys are written back with defaults on first load.

Key Default Description
default_max_chunks 25 Base chunk budget for every player. Permissions and bonus grants add to this.
map_grid_size 15 Side length of the claim map grid. Rounded up to the next odd number.
distance_between_claims 1 Minimum chunk buffer between different players’ claims. 0 disables the check.
wilderness_flags all Comma-separated flag names allowed in unclaimed land. Valid flags: BUILD,BREAK,INTERACT,CONTAINER,DOOR,PVP,FRIENDLY_FIRE,ENTRY,PORTAL,SIT,EXPLOSIONS,SPAWN.
claim_decay_time 30d Duration string (30d, 12h, 1d2h, etc.). Player claims are removed when the owner has been offline longer than this threshold. Set to 0 or empty to disable decay. Decay checks run on the rent_check_interval cadence.
rent_check_interval 300 Seconds between RentExpireTask and ClaimDecayTask runs.
rent_grace_days 3 Days a locked rent region stays locked before being reset.
expiry_warn_times 7d,1d,1h Comma-separated duration strings (e.g. 7d, 12h, 30m, 1d2h) marking how far before lease expiry a warning fires.
refund_on_reset false When true, the pro-rated remaining lease balance is refunded to the tenant on reset.
groups empty Comma-separated list of server-wide permission-group IDs (e.g. admin,moderator). Each entry creates a questlinesclaims.group.<id> permission node and is auto-seeded as a Permission Group on every region and claim. See Permission Groups for details. Reserved IDs (owner, trusted, untrusted) are ignored.

Database

Region and claim data is stored in a SQL database. SQLite is the default and keeps a local file at mods/QuestLinesClaims/claims.db. Switch to MySQL or MariaDB by setting database_type and filling in the connection parameters. Database changes require a server restart.

Key Default Description
database_typesqlitesqlite, mysql, or mariadb.
database_hostlocalhostRemote database host (ignored for SQLite).
database_port3306Remote database port.
database_namequestlinesclaimsSchema / database name.
database_userrootConnection user.
database_passwordemptyConnection password.
database_use_sslfalseRequest SSL in the JDBC URL.
database_extra_paramsemptyRaw parameters appended to the JDBC URL.

Permissions

Permission Default Description
questlinesclaims.admin false Full admin access: wand, admin UI, region CRUD, schematic saves, /claim setowner, /claim addchunks, /claim reload, manage any claim or region, and bypass all protection checks (including ENTRY).
questlinesclaims.claim.use true Required to open /claim map and /claim rentbuy.
questlinesclaims.claim.chunks.<N> false Adds N chunks to the player’s claim budget. Multiple matching permissions stack (N ranges 1–500). Use a permission manager to grant e.g. questlinesclaims.claim.chunks.50 for a +50 tier.
questlinesclaims.group.<id> false Server-wide permission group membership. One node per ID listed in the groups config key. Any player holding the node is treated as a member of the matching region/claim group on every region they visit, with that group’s per-region flag set. See Permission Groups.

Permission Groups

Permission groups are server-wide ranks (e.g. admin, moderator, builder) defined once in the main config and applied automatically across every region and claim. They’re the cleanest way to give staff or VIP ranks access to all builds at once, without trusting them individually on every claim.

How it works. Each ID listed in groups in questlinesclaims.conf does three things at boot and on /claim reload:

  1. Advertises the permission node questlinesclaims.group.<id>. Grant it to a player or rank to make them a member of that group.
  2. Auto-seeds a matching Permission Group entry on every existing region and claim alongside Owner/Trusted/Untrusted, initialised with the Trusted default flag set. Newly created regions and claims pick the same seed up.
  3. During every protection check, a player holding the permission gets the group’s per-region flags on top of any UUID-keyed membership they already have. The two sources union additively — a regular member who also holds questlinesclaims.group.admin keeps everything their member group grants plus everything the admin group grants on that region.

Editing flags per region. Use the existing groups UI (the Groups button on a region or claim’s manage screen) to set the flag set for each permission group on each region independently — e.g. the builder rank could be given BUILD+BREAK on staff plots only, and nothing on production claims. The seeded group is marked built-in so it can’t be deleted from the region UI; remove the entry from groups in the main config instead to deactivate it.

Comparison with questlinesclaims.admin. questlinesclaims.admin is a hard bypass of all protection checks at the listener level — admins ignore claims and regions entirely. Permission groups go through the normal flag check, so their access is bounded by the flag set the region owner configured. Use admin for trusted operators; use permission groups for ranks that should have controllable, per-flag access.

Reserved IDs. owner, trusted, and untrusted are reserved built-in groups and are silently dropped if added to groups.

File Layout

Path Purpose
mods/QuestLinesClaims/questlinesclaims.conf Plugin-level settings (chunk limits, rent tuning, wilderness flags, database connection).
mods/QuestLinesClaims/claims.db SQLite store (when database_type=sqlite). Holds admin regions, rent/buy regions, player claims, region members, chunks, per-player data, and pending notifications.
prefabs/questlinesclaims/<regionId>.prefab Saved prefab snapshots for rent/buy regions, restored on reset.
