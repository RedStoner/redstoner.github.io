Arcade Plugin

Commands

Three commands total — /arcade for everyone, /arcade-wallet for everyone, and /arcade-debug for operators. No DLC pack adds any additional commands; every game is reachable through the lobby UI.

/arcade

Audience: all players, no permission required. Subcommands: none. Running /arcade either opens the lobby or, if the caller is already participating in a live (non-terminal) match, re-opens that match’s UI. The first time a player runs this (or right-clicks a cabinet), their wallet is auto-seeded with startingTokens and their display name is recorded into their profile.

/arcade-wallet

Audience: all players, no permission required. Subcommands:

Subcommand Effect
balance Shows your tokens, chips, daily-claim cooldown, and (if VaultUnlocked is wired in) your server-economy balance.
daily Claim dailyTokens. Cooldown is dailyCooldownHours from the last claim. Reports the remaining cooldown if not yet ready.
tokens-to-chips <tokens> Spend tokens to receive chips at chipsPerToken. Requires exchangeEnabled.
chips-to-tokens <tokens> Spend chips to receive tokens. The argument is the number of tokens you want; cost = tokens × chipsPerOneToken. Requires exchangeEnabled.
buy-tokens <count> Pay server money (via VaultUnlocked) at vaultCostPerToken per token. Requires vaultEnabled and a registered Vault economy provider.
sell-tokens <count> Receive server money at vaultPayoutPerToken per token. Same Vault gate. Tokens are refunded if the Vault deposit fails.
buy-chips <count> Pay server money at vaultCostPerChip per chip.
sell-chips <count> Receive server money at vaultPayoutPerChip per chip. Chips are refunded if the Vault deposit fails.

All Vault rates use BigDecimal arithmetic with HALF_UP rounding at scale 4. See Wallet & Economy for the rate-tuning fields and the “chips-to-tokens argument is tokens, not chips” gotcha.

/arcade-debug

Audience: operators only. Permission: questlinesarcade.admin — gated on both the parent command and on every subcommand. Subcommands:

Match operations

SubcommandEffect
create <gameId> Allocate a new match in LOBBY state for the named game and report its match code.
list Print every registered game id and every active match (id, code, game, state, player count).
join <code> Join an existing match by code and open its UI.
start <code> Force-start a match in LOBBY state. Charges the entry fee just like a normal start.
leave Leave your current match. In LOBBY this just reclaims your seat; in RUNNING this forfeits.
hot-seat <gameId> [--players=N]Create a solo-testing match where the caller drives every role. N defaults to the game’s maxPlayers and is clamped to [minPlayers, maxPlayers]. The match force-starts immediately. Bypasses turn ownership in the input router so a single player can act on every turn.
clear Cancel every live match. Use sparingly.

Inspection

SubcommandEffect
stats Print the caller’s profile — totals and per-game Elo.
leaderboard <gameId> Print the cached top-N leaderboard for the named game.
wallet <player> Inspect another (online) player’s wallet.

Queue and invites

SubcommandEffect
queue <gameId> Place yourself in that game’s queue. Same path the lobby UI uses; subject to the affordability check.
leave-queue Leave whichever queue you’re in.
invite <player> <gameId>Send a 5-minute invite to an online player for the named game.
invites List the invites you currently have outstanding.

Wallet grants

All three accept negative amounts to deduct.

SubcommandEffect
add-tokens <player> <amount>Grant (or deduct) tokens to an online player.
add-chips <player> <amount> Grant (or deduct) chips to an online player.
key-probe Open the debug page that demonstrates the ValueChanged-on-TextField keystroke-capture pattern used by every text-input game. For internal validation only.
ℹ
Player name resolution is online-only

Every subcommand that takes a player name looks the target up in the live online roster. Offline players cannot be targeted — add-tokens on an offline player will not modify their profile.

Permissions

Node Default Grants
questlinesarcade.admin Operators only Access to every /arcade-debug subcommand.

/arcade and /arcade-wallet are not permission-gated; every player can run every subcommand. Per-server access is typically controlled at the chat or world level.
